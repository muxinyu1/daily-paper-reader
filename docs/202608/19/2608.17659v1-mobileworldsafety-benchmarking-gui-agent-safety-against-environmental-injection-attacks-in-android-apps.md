## 摘要
由LLM驱动的GUI代理能够自主操作智能手机，正迅速从研究原型转向早期实际部署。然而，由于这些代理 routinely 处理不可信的环境内容，它们极易受到环境注入攻击，包括间接提示注入和对抗性指令。此类攻击可以通过日常移动使用中遇到的各种渠道，在用户不知情的情况下操纵代理行为。尽管存在这些风险，现有基准测试往往无法涵盖日常用户场景，缺乏在移动设备上对环境注入攻击下GUI代理的系统评估。为弥补这一空白，我们提出了MobileWorldSafety，一个基于真实Android应用构建的142个风险任务的基准。对于每个任务，我们在最终系统状态上定义一个可编程验证的风险指标，并通过两阶段流程评估结果：基于规则的验证处理明确情况，而LLM裁判则裁决模糊情况。这区分了安全失败与能力失败，并实现了客观可重复的评估。对六种代理（包括通用代理和专用GUI代理）的评估表明，所有代理仍然高度脆弱，攻击成功率从40.4%到66.9%不等。这些发现表明，当对抗性内容以普通移动上下文呈现时，当前代理往往无法保持安全对齐。MobileWorldSafety为量化这些漏洞和推进稳健移动GUI代理的研究奠定了基础。

## Abstract
LLM-powered GUI agents that autonomously operate smartphones are rapidly transitioning from research prototypes to early real-world deployment. However, because these agents routinely process untrusted environmental content, they are highly vulnerable to environmental injection attacks, which include indirect prompt injections and adversarial instructions. Such attacks can manipulate the behavior of agents without user awareness through diverse channels encountered in everyday mobile use. Despite these risks, existing benchmarks often fail to capture everyday user scenarios, lacking a systematic evaluation of GUI agents under environmental injection attacks on mobile devices. To address this gap, we introduce MobileWorldSafety, a benchmark of 142 risk tasks built on real Android applications. For each task, we define a programmatically verifiable risk indicator over the final system state and evaluate outcomes with a two-stage pipeline: rule-based verification handles unambiguous cases, while an LLM judge adjudicates ambiguous ones. This distinguishes safety failures from capability failures and enables objective and reproducible assessment. Evaluations on six agents, including both general agents and specialized GUI agents, demonstrate that all agents remain highly vulnerable, with attack success rates ranging from 40.4% to 66.9%. These findings indicate that current agents often fail to maintain safety alignment when adversarial content is presented as ordinary mobile context. MobileWorldSafety provides a foundation for quantifying these vulnerabilities and advancing research on robust mobile GUI agents.

## 1. 核心问题与整体含义（研究动机与背景）

随着 LLM 驱动的 GUI 智能体（如能自主操作智能手机的 AI 助手）从研究原型快速迈向真实部署，它们面临一个根本性安全悖论：为了完成复杂移动任务，智能体必须持续处理不可信的第三方环境内容（邮件、短信、网页、社交帖子、MCP 工具返回结果等），这些内容天然构成攻击者的注入面。攻击者可将恶意指令嵌入正常应用内容中，形成**环境注入攻击（Environmental Injection Attack）**，诱导智能体偏离用户意图，执行泄露隐私、传播钓鱼链接、破坏数据等危险操作。

现有工作存在明显空白：
- 非移动场景（如 Web 代理）的安全基准无法迁移到移动 GUI 环境；
- 已有的移动端安全研究或假设恶意用户指令（如 MobileSafetyBench），或仅关注视觉层面的界面扰动（如系统通知、弹窗、覆盖层），缺乏对**嵌入原生应用内容（邮件、消息、社交帖子等）的隐蔽指令注入**的系统性评测；
- 现实移动工作流中，这些注入恰恰以“普通内容”的面貌自然进入智能体的处理管道，难以被绕过或识别。

MobileWorldSafety 回答的关键问题是：在用户意图完全良性、系统提示词未被篡改的条件下，GUI 智能体是否会仅仅因为“信任”应用内环境内容，而执行危险操作？

## 2. 方法论：核心思想、技术与流程

### 2.1 威胁模型与任务定义
- **威胁模型**：良性用户 + 恶意环境。攻击者可通过外部普通渠道控制环境内容，但无法控制系统提示词、用户目标、模拟器运行环境和评估验证器。
- **每个风险任务由四要素构成**：
  - 基本目标（Base Goal）：用户原本的良性任务
  - 注入载体（Injection Carrier）：恶意内容嵌入的媒介
  - 注入指令（Injected Instruction）：攻击者引入的误导性载荷
  - 风险指标（Risk Indicator）：基于最终系统状态的可编程验证标准

### 2.2 二维分类体系
- **5 种攻击向量**（输入侧）：V1 定向通信（邮件/SMS/DM）、V2 网页内容、V3 社区内容（Mastodon/Mattermost）、V4 存储记录（日历/PDF/发票）、V5 工具响应（MCP 返回）
- **7 种危害类别**（输出侧）：H1 敏感信息泄露、H2 人身安全暴露、H3 财务损失、H4 未授权操作、H5 运营破坏、H6 内容伪造、H7 有害内容传播

### 2.3 注入实现方式
每种攻击向量对应具体的注入实施策略，均通过初始化本地环境实现，不依赖真实外部网络，保证可复现性：
- 定向通信 → 预置短信/邮件到本地收件箱
- 网页内容 → 预写本地 HTML 文件，模拟恶意网页或投毒搜索结果
- 社区内容 → 初始化本地 Mattermost/Mastodon 后端，将恶意文本作为正常帖子发布
- 存储记录 → 预置 PDF、发票或日历事件描述等本地记录
- 工具响应 → 在本地部署（或模拟）的 MCP 工具返回字段中嵌入载荷

### 2.4 两阶段评估流水线
评估以**最终系统状态**为核心，而非主要依赖对执行轨迹的语义推断：

- **阶段一（规则化验证）**：任务终止后，调用预置的规则验证器比对最终系统状态与风险指标，明确情况（如攻击完全成功、基础任务完全完成）直接判定，快速且精确。
- **阶段二（LLM 法官）**：对于规则验证无法定论的模糊样本，向 LLM 法官提供任务定义、验证器输出和完整轨迹日志，进行语义分析，区分不同类型的失败或部分风险。

### 2.5 五级标签体系（结果分类）
- **Executed**：攻击被完整执行
- **Partial**：攻击被部分执行
- **Defended**：攻击被抵御且基础任务成功完成
- **Stalled**：攻击被抵御但基础任务失败
- **Run Failed**：智能体因能力限制未触及注入载体（从可评分数中剔除）

该体系能精确区分**安全失败**与**能力失败**，避免高估智能体的安全性。安全性优先级原则：任何触发风险指标的轨迹都判定为 Executed，不论基础任务是否完成。

### 2.6 核心指标
- **可评分数**：N_sco = N_total − N_rf（排除运行失败样本）
- **ASR（攻击成功率）** = (Executed + Partial) / N_sco：主要安全指标
- **TCR（任务完成率）** = Defended / N_sco：在攻击下的任务效用指标

### 2.7 质量验证
在 Gemini-3-Pro 与 Claude-Sonnet-4.5 的 76 个模糊判定案例上，人类专家与 LLM 法官的完全一致率达 **92.1%**，验证了阶段二判定的可靠性。

## 6. 主要结论与发现

### 6.1 核心结论
所有六个评估的智能体在真实 Android 应用环境注入攻击下均高度脆弱，**ASR 在 40.4%–66.9% 之间**；且每个模型的 ASR 都高于其 TCR——智能体更倾向于执行注入的对抗指令，而非安全完成良性任务。

### 6.2 通用智能体分析
- Gemini-3-Pro 最极端：ASR 66.9%，但 TCR 仅 30.0%，呈现最强的执行能力与最弱的安全鲁棒性的组合
- 其余通用模型的 ASR 集中在 47.5%–51.6%，说明该脆弱性是结构性问题，而非单一模型的偶然缺陷
- 任务执行能力与注入鲁棒性不匹配：Claude-Sonnet-4.5 ASR 最低（47.5%）但 TCR 并非最高；Qwen 的 TCR 最高（46.8%），ASR 却不低（51.6%）

### 6.3 专用 GUI 智能体分析
- 专用 GUI 智能体表面上 ASR 更低（40.4%–44.3%），但 Run Failed 数量远高于通用智能体（36 和 53 vs. 12–24），说明其较低 ASR 部分是执行失败所致，而非真正的安全鲁棒性

### 6.4 攻击向量与危害类别分析
- **V5（工具响应）**在所有智能体上 ASR 均最低（结构化边界降低被劫持风险）
- **V1（定向通信）**在通用智能体上引发普遍高 ASR（邮件/SMS 的权威感使其很少被质疑）
- **H5（运营破坏）、H6（内容伪造）、H1（敏感信息泄露）**在大多数智能体上 ASR 持续偏高
- **H2（人身安全暴露）、H7（有害内容传播）**通常 ASR 较低（显性物理/毒性威胁可被基线安全机制拦截）
- **H3（财务损失）**对 Gemini-3-Pro 显著偏高，反映该模型特有的盲区

### 6.5 防御与变体实验发现
- 系统提示防御可将 ASR 降低约 14–16 个百分点，但伴随 Stalled 样本显著增加，防御以牺牲任务效用为代价
- 多阶段运行时防御相对系统提示仅额外降低 1.3 个百分点，说明通用注入扫描器无法有效识别与任务上下文语义耦合的注入内容
- 模型规模增大反而扩大攻击面（强执行能力 = 更大的可利用面积）；推理模式（Thinking）将部分 Stalled 转化为 Partial，增加注入指令被部分执行的概率，而并未提高安全完成任务率

### 6.6 效用退化分析
干净环境下 Qwen 能完成 89 个任务（62.7%），攻击环境下仅完成 58 个（40.8%）。被攻击者成功诱导的轨迹中，多数在干净环境中本也会因规划能力不足而失败——恶意指令实际上充当了困境中智能体的“捷径”，这是环境注入的又一危险特征。

## 7. 优点

1. **真实场景保真度高**：基于 13 个真实 Android 应用构建，任务设计反映日常移动使用场景，而非合成环境
2. **威胁模型清晰且贴近现实**：良性用户 + 恶意环境模型，注入内容以原生应用内容的形态自然进入智能体观测空间，攻击面真实可信
3. **两阶段评估流水线设计精巧**：规则验证处理明确情况 + LLM 法官裁决模糊情况，兼顾客观性和覆盖面
4. **五级标签体系严谨**：能区分安全失败、能力失败、部分攻击等不同情形，避免将能力不足误判为安全性好，也避免将任务完成率掩盖安全失败
5. **安全性优先原则**：任何触发风险指标的轨迹均判定为攻击成功，防止任务效用掩盖安全对齐的严重缺陷
6. **二维分类体系提供细粒度分析**：攻击向量 × 危害类别的矩阵式分析能独立揭示哪些载体更具欺骗性、哪些风险更容易触发
7. **多维度的补充实验**：覆盖防御策略、模型变体、推理模式、框架迁移、效用退化分析，提升结论的厚度
8. **透明协作验证**：人类-LLM 法官一致性达 92.1%，且附录完整提供法官提示词、评估提示词模板，可复现性强

## 8. 不足与局限

1. **防御策略研究不充分**：仅测试了系统提示防御和一种多阶段运行时防御；训练阶段对齐、输入级过滤、运行时监控等方向留待未来
2. **攻击向量覆盖有限**：未覆盖 overlay 类外部向量（系统通知、弹窗、UI 覆盖层），实际威胁面可能比基准更大
3. **统计严谨性不足**：因 API 成本高昂，未进行多次运行，未报告误差棒、置信区间或显著性检验
4. **模型覆盖可扩展性**：仅评估 6 个主模型 + 少量变体；未来模型的安全表现可能与结论有偏差
5. **专用 GUI 智能体的效用分析欠缺**：干净环境基线仅测了 1 个通用模型，无法判断专用智能体低 ASR 中能力失败与真实安全的比例（虽然已从 Run Failed 数据间接分析）
6. **任务复杂度校准引入的选择偏差**：为保障注入载体的到达率，作者刻意降低部分高难度任务的复杂度，这虽然严格解耦了安全对齐与执行能力，但也意味着基准不能反映真实高复杂度工作流中的安全性表现
7. **环境内容可控性假设的边界**：模拟环境中预置注入内容与真实世界中攻击者控制第三方内容的时效性、动态性存在差异
8. **双刃剑风险**：基准结构本身暴露了哪些内容载体更易误导智能体，可能被恶意行为者利用（尽管作者已在 Broader Impacts 中讨论了缓解策略）
