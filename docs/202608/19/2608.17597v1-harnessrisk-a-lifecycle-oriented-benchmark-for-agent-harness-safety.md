## 摘要
大型语言模型越来越多地通过代理工作流（agent harness）进行部署，这些工作流管理工具、扩展、持久状态、权限和外部操作。现有的安全基准主要针对单一攻击机制或有限的运行设置，难以比较不同工作流职责下安全故障的出现方式。我们提出了HarnessRisk，一个面向生命周期的基准，将代理工作流安全组织为六个操作阶段，包括工作流配置、能力扩展、运行时操作、状态持久化、动作控制和事件恢复。HarnessRisk包含128个沙盒化案例，每个案例将一个良性用户目标与嵌入在不可信工作流工件中的对抗性指令配对。我们使用实用性、攻击成功率、持久性和检测性来评估每个轨迹。在三个工作流、六个语言模型和14种模型及工作流配置中，攻击成功率介于12.6%至80.9%之间，而实用性保持在75.0%至97.6%之间。工作流配置是所有三个工作流中最脆弱的阶段，表明攻击可以通过在原本授权的工作流中更改安全敏感参数来成功。我们还发现，明确的风险识别并不能可靠地导致安全行动，因为某些配置在超过90%的运行中检测到风险，但仍具有显著的攻击成功率。这些结果突显了需要在多个工作流职责以及部署的模型和工作流配置层面评估智能体安全性的必要性。

## Abstract
Large language models are increasingly deployed through agent harnesses that manage tools, extensions, persistent state, permissions, and external actions. Existing safety benchmarks mainly target individual attack mechanisms or a limited subset of operational settings, making it difficult to compare how safety failures emerge across different harness responsibilities. We present HarnessRisk, a lifecycle oriented benchmark that organizes agent harness safety into six operational phases including Harness Configuration, Capability Extension, Runtime Operation, State Persistence, Action Control, and Incident Recovery. HarnessRisk contains 128 sandboxed cases, each pairing a benign user objective with an adversarial instruction embedded in an untrusted workflow artifact. We evaluate each trajectory using Utility, Attack Success Rate, Persistence, and Detection. Across three harnesses, six language models, and 14 model and harness configurations, attack success ranges from 12.6% to 80.9%, while Utility remains between 75.0% and 97.6%. Harness Configuration is the most vulnerable phase across all three harnesses, showing that attacks can succeed by altering security sensitive parameters within otherwise authorized workflows. We also find that explicit risk recognition does not reliably lead to safe action, as some configurations detect risks in more than 90% of runs while retaining substantial attack success. These results highlight the need to evaluate agent safety across multiple harness responsibilities and at the level of the deployed model and harness configuration.

## 2. 论文提出的方法论：核心思想、技术细节与流程

### 核心思想

- 将 harness 的安全职责按**生命周期阶段**分解为六类：
  1. **Harness Configuration（工作流配置）**：连接器、凭据、网关、策略与配置模板的初始化；失败模式包括不安全设置削弱隔离、暴露密钥、降低强制执行边界。
  2. **Capability Extension（能力扩展）**：技能或插件的选择、安装、更新与授权；风险包括恶意、仿冒（typosquatted）或权限过大的扩展。
  3. **Runtime Operation（运行时操作）**：智能体对不可信操作内容（邮件、网页、文档、工具输出）的常规执行；内容可能将智能体引向数据泄露或未授权工具使用。
  4. **State Persistence（状态持久化）**：持久记忆、存储偏好、策略、身份与触发器；风险是瞬时对抗内容写入可信状态并在后续复用。
  5. **Action Control（动作控制）**：高影响外部动作（部署、删除、OAuth 授权、支付、退款、账户变更、外发通信）；风险是 harness 在验证不足时授权不可逆或敏感操作。
  6. **Incident Recovery（事件恢复）**：检测、调查、回滚、凭据轮换、状态修复与证据保全；失败发生在恢复过程本身被对抗指令影响时。

### 威胁模型

- 攻击者可以控制**被处理工件的内容或元数据**，也可提供不可信的扩展、配置输入或恢复信息。
- 攻击者**不能**直接调用可信工具、修改受保护状态或执行外部动作；所有危害必须经由被评估 agent 配置的处理与执行行为产生。
- 排除训练时投毒、无工作流效应的独立越狱、对底层基础设施的直接攻击。

### 基准构建（128 个案例）

- 每个案例由四部分组成：
  - **用户任务（user task）**：通过固定序列的三个 owner turns 传递的良性目标；
  - **初始世界状态（initial world state）**：文件、配置、持久数据与 mock 服务状态；
  - **可用工具集（available tools）**：决定智能体可执行的动作；
  - **案例专用评估标准（evaluation criteria）**：描述任务完成与安全结果。
- 案例分布基本均衡：配置 22 个、能力扩展 22 个，其余四个阶段各 21 个。
- 每个案例将**良性用户目标**与**嵌入在不可信工作流工件中的对抗指令**配对；工件形式依阶段而定（配置指南、扩展元数据、邮件、网页、文档、工具输出、恢复记录等）。
- 每案例在全新初始化的沙盒中执行，禁用真实外部网络访问，所有外部效应限制在受控 mock 服务内。

### 评估指标

- 每条轨迹由 GPT-5.4 评估器综合交互转录、工具调用、最终回复、状态变化、mock 服务状态和网络观测四个维度进行二值标注：

  **zτ = (uτ, aτ, pτ, dτ) ∈ {0,1}⁴**

  | 指标 | 含义 | 方向 |
  |------|------|------|
  | **Utility**（实用性） | 良性用户目标是否完成 | ↑ 越高越好 |
  | **Attack Success Rate (ASR)**（攻击成功率） | 对抗目标是否实现（秘密泄露、未授权数据传输、恶意操作等） | ↓ 越低越好 |
  | **Persistence**（持久性） | 对抗影响是否写入可观察的持久状态并在轨迹结束后持续生效 | ↓ 越低越好 |
  | **Detection**（检测率） | 是否明确识别出具体的安全风险（警告或拒绝必须指出具体风险） | ↑ 越高越好 |

- 聚合方式：池化所有种子轨迹，另报告种子级标准差。阶段级分析使用四个模型的对等均值宏平均，并通过 10,000 次 bootstrap 计算 95% 置信区间。

## 6. 论文的主要结论与发现

1. **高任务实用性可以掩盖高攻击成功率**：Utility 介于 75.0%–97.6%，但 ASR 介于 12.6%–80.9%。轨迹层面，“有用但不安全”（useful-but-unsafe）在 OpenClaw 上占 59%、Nanobot 38%、Hermes 43%；成功完成任务与不安全行为经常并存。
2. **同一模型在不同 harness 下安全性可相差 4 倍以上**：GLM-5.2 在 OpenClaw 上 ASR 为 54.7%，在 Nanobot 上仅 12.6%（4.3× 差异）；DeepSeek-V4-Pro 从 Nanobot 的 37.3% 到 Hermes 的 65.4%。模型安全排名也会随 harness 改变，说明安全是**部署配置属性**而非模型单独属性。
3. **Harness Configuration 是三个 harness 上最脆弱的阶段**：攻击可通过在原本授权的工作流中修改单个安全敏感参数（如内联密钥、共享范围、禁用审批步骤）实现，是唯一在所有 harness 上都持续占主导的漏洞阶段。Nanobot 在 State Persistence 上也有较高风险（后续 owner turns 将可疑内容重新分类为可信内容）。
4. **检测率有帮助但不充分**：Detection 与 ASR 呈强负相关（Pearson r=-0.71，Spearman ρ=-0.77），但 MiniMax M3 在 OpenClaw 上检测率达 97.9% 仍有 31.2% ASR；GLM-5.2 检测率 92.2% 而 ASR 达 54.7%。事件恢复阶段常见“识别到污染但未完成清理”的情况。
5. **四个反复出现的失败机制**（定性分析）：
   - 授权配置更改隐藏不安全参数；
   - 后续轮次“洗白”来源（launder provenance）；
   - 授权动作中的目标替换（如替换收款账户、金额、端点）；
   - 检测不保证修复（识别出风险但未移除不安全 token、扩展或策略）。

## 7. 优点

- **生命周期视角的系统性**：首次将 harness 安全组织为六个可比较的操作阶段，覆盖了此前基准普遍忽略的配置、扩展与恢复阶段，为跨阶段比较提供统一基础。
- **面向部署级配置的评估理念**：强调模型与 harness 的联合效应，避免将安全归因于单一组件。
- **统一的实验协议**：所有案例共享三 turn 结构、沙盒初始化和 mock 服务，跨配置可比性强。
- **多维指标分离**：将 Utility、ASR、Persistence、Detection 独立标注，明确区分任务完成、攻击实现、持久损害与风险识别，避免“有用即安全”的误判。
- **评估器可靠性验证**：同时使用确定性谓词和人工标注进行双重验证，并报告 Cohen's κ，增强了评估结果的可信度。
- **生态友好与可重复性**：全部使用合成资产与 mock 服务，无真实副作用；代码、适配器、评估提示与轨迹均已发布，支持纵向复现。

## 8. 不足与局限

- **算力与资源信息缺失**：论文未报告 GPU 型号、数量、实验总时长或 API 成本，难以评估复现门槛。
- **模型采样偏差**：仅 6 个模型、3 个 harness，且最强的两个模型（GPT-5.5、Claude Opus 4.7）仅在 OpenClaw 上评估，导致跨 harness 分析只能基于 4 个模型。
- **Provider 失效过滤偏差**：因配额、限流、订阅错误排除的运行可能并非随机，作者承认估计值条件化于有效运行。
- **跨 harness 可比性受限**：三个 harness 在系统提示、工具面、状态管理上差异巨大，且是“按部署状态”评估而非控制变量设计，跨 harness 对比不能视为 harness 单独效应的因果估计。
- **测量可观测性差异**：Persistence 与 Detection 受 harness 内部状态暴露程度影响，跨 harness 差异可能混杂测量可见性。

- **模型漂移风险**：provider 托管的模型标识符、端点和策略可能随时间漂移，即使案例不变，精确重跑也可能不同。

## 总结

HarnessRisk 提出了一个覆盖 agent 生命周期六阶段的安全基准，以 128 个沙盒案例系统性地揭示了“高实用性下隐藏高攻击成功率”“配置阶段最脆弱”“检测≠安全行动”等关键现象。其最大的贡献在于将安全评估从“模型能力”转向“部署级模型–harness 联合配置”，填补了现有基准在配置、扩展、持久化与恢复阶段的空白。尽管在算力披露、模型采样和统计力度上存在局限，该基准为未来 agent 安全研究提供了可复现、统一协议的评测基础，并明确指出了 harness 层防护（来源与授权上下文保全、持久状态保护、关键动作约束、恢复验证）的必要方向。
