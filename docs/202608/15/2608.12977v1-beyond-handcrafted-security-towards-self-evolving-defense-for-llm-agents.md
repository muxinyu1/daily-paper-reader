## 摘要
大语言模型（LLM）代理不断扩展的操作能力引入了复杂的安全威胁。运行时防御通过将安全机制集成到代理执行循环中，已成为缓解这些风险的有效方法。然而，现有的运行时防御严重依赖人工设计的干预措施，缺乏构建和维护这些措施的原则性框架。在本工作中，我们首先开发了一种基于工具层的运行时防御形式化描述，系统性地表征了工具机制如何实现防御构建，并从工具视角提供了现有运行时防御干预措施的统一视图。基于此形式化，我们提出了HARD（基于工具的自演化运行时防御），一种自演化运行时防御框架，能够自动识别适当的干预策略，并根据观察到的失败痕迹迭代改进防御构件。HARD将运行时防御的开发从人工工程转变为自主演化过程，大量实验表明，它在现有手工防御的基础上提升了安全性能，同时保持了良性任务效用。我们的研究结果强调，自主防御演化是保护已部署LLM代理的一种有前景的新范式，使代理能够识别防御弱点并持续改进其保护机制。

## Abstract
The expanding operational capabilities of large language model (LLM) agents introduce sophisticated security threats. Runtime defenses have emerged as an effective approach to mitigating these risks by integrating security mechanisms into the agent execution loop. However, existing runtime defenses rely heavily on manually designed interventions and lack a principled framework for their construction and maintenance. In this work, we first develop a harness-level formulation of runtime defense that systematically characterizes how harness mechanisms enable defense construction and provides a unified view of existing runtime defense interventions from a harness perspective. Building on this formulation, we propose HARD (Harness-based Autonomous Runtime Defense Evolution), a self-evolving runtime defense framework that automatically identifies appropriate intervention strategies and iteratively improves defense artifacts based on observed failure traces. HARD transforms runtime defense development from manual engineering into an autonomous evolution process, and extensive experiments demonstrate that it improves security performance over existing handcrafted defenses while preserving benign task utility. Our findings highlight autonomous defense evolution as a promising new paradigm for securing deployed LLM agents, enabling agents to identify defense weaknesses and continuously improve their protection mechanisms.

- **研究问题**：如何使运行时防御能够基于新观察到的失败痕迹**自主演化**，以适应不断涌现的攻击？

## 2. 论文提出的方法论

### 2.1 核心思想

论文的核心思想是：将运行时防御的构建与维护形式化为**基于可编辑代理工具层（harness）的优化问题**，并通过LLM驱动的演化器，利用失败执行轨迹作为反馈信号，自动迭代改进防御构件，实现从"人工工程"到"自主演化"的转变。

### 2.2 关键技术细节

**（1）工具层（Harness）形式化框架**

- 将LLM代理建模为 A = (M_θ, H)，其中 M_θ 是参数固定的语言模型，H 是协调模型与外部环境和持久化构件交互的运行时工具层。
- 工具层由两个核心函数构成：**上下文构建函数 φ_H**（决定向模型呈现哪些信息）和**动作解释函数 ψ_H**（决定模型输出如何被翻译为可执行操作，包括解析、验证、转换、阻止或请求确认）。
- 该形式化提供了一个统一视角：所有现有运行时防御本质上都是在优化 φ_H、ψ_H 或两者。防御目标可表述为：
  - H ⋆ = argmax E[J_safe(τ) + λ_u · J_util(τ)]
  - 其中 J_safe 为轨迹安全性能，J_util 为任务效用，λ_u 为效用权重。

**（2）HARD 框架的演化流程（Algorithm 1）**

HARD 包含三个主要步骤，循环迭代 T 轮：

1. **攻击驱动轨迹收集**：从攻击任务分布中采样任务 X_t，在当前工具层 H_t 下收集执行轨迹 T_t。
2. **失败识别**：根据安全阈值 δ_s 和效用阈值 δ_u，筛选出失败轨迹集合 F_t。
3. **工具层演化**：将失败集合交给LLM演化器 E，在最小改动约束下生成更新的工具层 H_{t+1}。

**（3）失败痕迹路由与定向演化**

- **可编辑防御构件**：将工具层划分为 K 个可独立编辑的防御构件（论文实例化为两个：上下文侧安全策略 policy 和动作侧防御规则 gate）。
- **痕迹驱动路由**：LLM路由器 R 分析每条失败轨迹，将其归因到最应当负责的防御构件（k = R(τ)），形成构件专属的反馈集 F_{k,t}。
- **构件定向演化**：每个构件使用各自的演化器 E_k 和反馈集进行独立更新（d^{t+1}_k = E_k(d^t_k, F_{k,t})），然后组装为更新的工具层。
- **路由规则**：需要语义推理的失败路由到 policy 演化的器；具有可复用、低误报的执行时谓词的失败路由到 gate 演化器。gate 置信度低于 0.55 时重新分配至 policy。

**（4）演化器设计**

- **Policy 演化器**：以"最小变更"为约束，倾向合并和泛化已有规则，提取底层安全不变量（如凭证窃取、权限提升、不可逆破坏等），避免针对特定痕迹的过度拟合，并注意在修复合法的良性用途与阻断滥用之间保持平衡。
- **Gate 演化器**：仅生成针对当前批次失败的新规则，规则必须是对工具名和参数的机器可匹配的执行时谓词，强调可复用结构和低误报，避免针对基准专用路径的过度匹配。

## 6. 论文的主要结论与发现

- **HARD 全面优于手工防御**：在静态攻击下，HARD-Both 将 ASR 降至 DPI 15.4%、IPI 1.0%、MC 6.7%、SP 10.2%（对比手工防御的 13–66%），同时保持 91.9–95.0% 的 BU。
- **显著提升攻击下效用**：MC 的 UA 从 56% 提升至 86%，SP 的 UA 从 52% 提升至 92%，说明防御抑制了对抗目标而并未牺牲用户任务。
- **防御构件互补性**：在静态攻击下联合演化（HARD-Both）最优；在自适应攻击（尤其是 LPA）下，HARD-Policy 反而优于 HARD-Both（ASR 4.8% vs 12.1%），说明确定性 gate 规则在分布转移时泛化能力有限，甚至可能削弱 policy 学习可转移原则的压力。
- **演化骨干选择影响安全-效用权衡**：所有骨干均显著降低 ASR，但 Claude Opus-4.6 最低 ASR（7.7%）、GLM-5.2 最高 UA（85.9%）、Qwen3.7-Max 最高 BU（96.4%）、GPT-5.5 将 UA 降至 7.2%（过度严格）。
- **单次失败足以触发修复**：案例研究表明，一个观察到的失败痕迹就能让 HARD 合成有效的防御，但前提是演化出的构件匹配失败的质性——可执行模式适合 gate 规则，语义性失败需要 policy 泛化。

## 7. 优点

- **统一理论框架**：提出工具层中心的形式化，将散乱的运行时防御工作统一到一个优化框架下，为领域提供概念基石。
- **自主演化范式创新**：首次将运行时防御的开发从依赖人工迭代诊断编辑的模式，转变为基于失败反馈的自主演化流程，消除人工瓶颈。
- **定向路由机制设计巧妙**：通过 LLM 路由器将失败归因到具体防御构件，实现目标明确的演化而非整体盲目改动；两种演化器各有清晰的关注点且相互隔离，降低重叠和冲突。
- **公平且严谨的评估**：确定性的数据划分、固定的执行代理与评估器、多种统计检验、明确区分训练/测试的泛化评估。
- **诚实的分析**：实验分析不仅报告了整体改进，还揭示了联合演化在自适应攻击下的不足，说明了不同防御构件的适用边界。
- **案例研究深入**：端到端演化示例展示了失败驱动演化的微观机制，增强了结果的可解释性。

## 8. 不足与局限
