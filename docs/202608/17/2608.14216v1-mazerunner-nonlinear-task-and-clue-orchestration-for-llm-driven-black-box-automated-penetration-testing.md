## 摘要
渗透测试至关重要但资源密集。尽管大型语言模型（LLMs）在自动化安全审计方面显示出潜力，但现有代理主要是在简化的线性场景中执行端到端工作流。现实世界的黑盒测试本质上是非线性的：攻击图最初未知，必须从环境反馈中逐步推断。观察可能会揭示多个攻击分支，失败通常具有模糊性，关键线索可能跨越长时间的动作跨度。因此，现有代理容易陷入深度优先探索、误诊失败并遗忘先前的证据。我们提出了MazeRunner，一个基于三代理任务与线索编排框架的自主渗透测试系统。它分离了全局编排、上下文密集型执行和面向失败的审查，同时持续维护任务状态和环境证据。这种设计支持行动修正、前提恢复、分支切换和长距离线索关联。我们在10个最新发布的HTB目标上评估了MazeRunner，将每次系统-目标运行限制为2000万个LLM令牌，并防止特定于目标的解决方案泄露。使用Claude Sonnet 4.5，MazeRunner完成了47.7%的带注释子任务，而PentestGPT-V2为36.2%，Claude Code为34.2%。它在六个目标上实现了用户级或更高访问权限，其中两个获得了根访问权限；每个同模型基线仅在两个目标上达到用户级访问权限，且从未获得根访问权限。执行轨迹分析进一步表明，MazeRunner探索了更多的攻击分支，并且更高效地获取了shell。

## Abstract
Penetration testing is essential yet resource-intensive. Although large language models (LLMs) show promise for automating security auditing, existing agents mainly execute end-to-end workflows in simplified linear scenarios. Real-world black-box testing is fundamentally nonlinear: the attack graph is initially unknown and must be incrementally inferred from environmental feedback. Observations may reveal multiple attack branches, failures are often ambiguous, and critical clues may span long action horizons. Existing agents therefore tend to become trapped in depth-first exploration, misdiagnose failures, and forget prior evidence. We present MazeRunner, an autonomous penetration testing system built on a three-agent task-and-clue orchestration framework. It separates global orchestration, context-intensive execution, and failure-oriented review while persistently maintaining task states and environmental evidence. This design supports action revision, prerequisite recovery, branch switching, and long-range clue correlation. We evaluate MazeRunner on 10 recently released HTB targets, limiting each system-target run to 20 million LLM tokens and preventing target-specific solution leakage. With Claude Sonnet 4.5, MazeRunner completes 47.7% of annotated subtasks, compared with 36.2% for PentestGPT-V2 and 34.2% for Claude Code. It achieves user-level or higher access on six targets, including root access on two; each same-model baseline reaches user-level access on only two targets and never obtains root access. Execution-trace analysis further shows that MazeRunner explores more attack branches and acquires shells more efficiently.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：渗透测试是网络安全评估的核心手段，全球年支出达 27.4 亿美元（2025 年），但高度依赖人工专家，成本高、效率低、难以规模化。LLM 的出现为自动化渗透测试带来了新机遇，已有多个系统（如 PentestGPT、PentestAgent、AutoPT、PentestGPT-V2 等）尝试利用 LLM 实现自动化。
- **核心问题**：现有 LLM 驱动的渗透测试智能体大多只在简化的、线性的 CTF 式环境中有效。真实黑盒渗透测试具有三个根本性难点：
  1. **攻击图未知**：目标内部拓扑和攻击路径必须从环境反馈中逐步构建，而非预先给定；
  2. **非线性多分支**：一次观察可能引出多条可行攻击分支，失败往往语义模糊；
  3. **长跨度线索关联**：决定后期成败的关键线索可能在数十步之前就已出现，普通上下文窗口无法承载。
- **现有系统的三大瓶颈**：
  - **编排缺陷与“深度优先陷阱”**：任务失败后智能体容易过度锚定局部分支，反复低效重试，导致目标漂移和幻觉任务；
  - **上下文失忆**：有限上下文窗口无法容纳长时间交互产生的海量反馈，导致任务与线索被忽略或遗忘；
  - **错误归因偏差**：LLM 难以准确跟踪状态和进行根因分析，失败后容易错误关联无关任务，过早放弃可行攻击路径。
- **核心论点**：有效的自主渗透测试必须超越“漏洞匹配 + 工具调用”的简单范式，需要具备**错误识别与回溯能力**、**跨阶段线索持久化与整合能力**，以及**动态非线性任务编排能力**。

## 2. 方法论：MazeRunner 系统设计

### 2.1 核心思想

MazeRunner 提出了一种**三智能体任务与线索编排框架**，将渗透测试过程解耦为三个角色：

- **Strategist（战略家）**：负责全局任务编排，将高层目标分解为动态任务图，并根据执行反馈持续修正、剪枝、切换分支；
- **Executor（执行者）**：负责上下文密集的环境交互，将任务转化为具体 CLI 命令/脚本，收集环境证据；
- **Reviewer（审查者）**：独立进行面向失败的分析，诊断失败根因，提供可操作的结构化反馈，指导重新规划。

三者构成“**计划→执行→审查→再计划**”的闭环工作流。

### 2.2 关键技术细节

- **持久化任务与线索缓存（Task & Clue Cache）**：
  - 核心基础设施，将“任务”和“线索”作为基本原语独立持久化管理；
  - **任务图（Task Graph）**：维护任务依赖关系（DAG）、执行状态、拓扑结构，任务状态严格分为六类：`pending`、`ready`、`running`、`completed`、`failed`、`blocked`；
  - **线索图（Clue Graph）**：存储结构化环境证据（开放端口、配置片段、凭证、漏洞信息等），并显式建立线索的“生产者任务”与“潜在消费者任务”之间的映射，支持跨阶段推理；
  - 状态迁移中的确定性逻辑（如 `pending → ready`）由程序化逻辑处理，不消耗 LLM 推理；
  - 单一任务并发执行，通过阻塞机制防止上下文写入冲突。
- **任务创建与细化**：Strategist 生成“语义完整”的任务而非原子命令；任务带有描述、前置条件、相关线索和预期输出等元数据。
- **任务执行模式**：
  - **非交互模式**：适用于扫描、枚举等无状态操作；
  - **交互式 PTY 模式**：适用于需要保持会话状态的操作（如反弹 shell 稳定化、远程登录后的命令链）；
  - 执行轨迹与会话状态记录为任务节点元数据，但细粒度日志不提升为规划级节点，保持抽象层次清晰。
- **失败审查机制**：Reviewer 两阶段分析：
  1. 判定失败原因类型：高层攻击路径错误 / 局部执行问题（工具用法、命令构造、交互流程）/ 前置条件未满足；
  2. 检查执行输出中是否暴露新证据（用户名、路径、配置片段等）。
  - 对不可恢复的失败，标记下游任务为 `blocked` 并从调度集合中剪除，但保留已完成的上游任务及其线索供其他分支使用。
- **重新规划**：候选任务来源包括：
  1. 失败任务的局部修订重试；
  2. 新线索催生的全新任务；
  3. 回溯到有效上游节点后切换的替代分支。
- **三种典型干预模式**（通过运行实例说明）：
  - **局部任务调整**：如修正 PoC 中加密算法参数（A256GCM → A128GCM）后重试；
  - **前置条件补充**：如识别出缺少 vhost 发现任务，补充执行后找到 `mcp.kobold.htb`；
  - **分支切换**：如用户 shell 提权失败后，切换到密码哈希破解分支。
- **系统架构**：基于 Kimi Code CLI 编排三智能体；Kali Linux 后端执行 Nmap、Gobuster、ffuf、curl 等标准工具；MySQL 持久化存储；采用**数据流驱动的闲置监测**而非固定超时来缓解阻塞。
- **抗数据污染设计**：禁止访问目标特定 write-up/flag 泄露信息；允许访问通用漏洞数据库和公开 exploit 仓库（符合真实渗透场景）；人工审查浏览与命令轨迹，发现违规后丢弃污染后的动作。

## 6. 主要结论与发现

- **性能优势**：在 Claude Sonnet 4.5 下，MazeRunner 子任务完成率 47.7%（PentestGPT-V2 36.2%、Claude Code 34.2%）；获取 6 个用户级及以上访问（含 2 个 root），而两个基线均只获 2 个用户 shell、0 个 root。DeepSeek-V3.2 骨干下同样占优。GPT-5.2 / GPT-5.2-Codex 骨干下完成率约 47-48%。
- **探索广度**：MazeRunner 在 10 个目标上的探索广度（多分支决策数）中位数和均值均优于基线；Claude Code 表现出过早放弃倾向，PentestGPT-V2 倾向于单线程冗余循环。
- **失败模式分布**：MazeRunner 的规划错误（29.4% vs 55.0%/68.4%）和线索遗忘（5.9% vs 25.0%/21.1%）发生率显著低于基线；但其代码/载荷失败占比更高（52.9%），表明编排改进使系统进入更深执行阶段后，瓶颈转移到 exploit 兼容性和载荷正确性。
- **开销效率**：MazeRunner 在 token 效率和成本效率上优于基线（Sonnet 4.5 下每 100M token 获 4.85 个 shell vs 基线的 1.58/3.19；每 $10 获 1.24 个 shell vs 0.4/0.73）；PentestGPT-V2 消耗约 2 倍 token 后进度停滞。
- **消融结论**：移除 Cache 导致完成率降至 58.8%（-14.7pp）、token 增加 27.7%；移除 Reviewer 导致完成率骤降至 51.5%（-22.0pp）、token 激增 80.7%——Reviewer 是防止“深度优先陷阱”和资源浪费的关键组件。
- **Agent 开销分布**：Executor 消耗总 token 的 75%-95%，Strategist 和 Reviewer 仅占少量，但后两者的“小投入”显著避免了代价高昂的执行循环。
- **重要异常发现**：GPT-5.2-Codex 反而不如 GPT-5.2，推测其内置编排行为干扰了 MazeRunner 外部编排；另有观察指出，更强的前沿模型（如 Kimi K3）可以部分补偿外部编排的缺失，但这种方式成本和可控性较差，显式编排依然必要。
- **LLM 固有偏差**：规划时对常见攻击方法存在统计偏好，在需要罕见攻击向量时可能浪费大量迭代甚至过早放弃（如 HTB-Garfield 上错过 Kerberos 初始账户后门路径）。

## 7. 优点

1. **问题定位精准**：清晰识别出 LLM 渗透代理在“非线性黑盒”场景下的三个核心瓶颈（深度优先陷阱、上下文失忆、错误误归因），切中实际痛点。
2. **架构设计巧思**：将“任务状态”与“环境证据”分离并持久化外置，突破了 LLM 上下文窗口的固有限制；将失败审查独立为专门智能体，符合“感知-认知-执行”分离的系统工程原则。
3. **完全自动化目标明确**：不依赖预定义脚本或 MCP 处理器，使用标准 CLI 工具，通用性和可扩展性强。
4. **评估严谨性突出**：
   - 选择训练截止日期之后发布的靶机，系统性避免数据污染；
   - 明确禁止并检测 write-up 知识泄漏；
   - 统一 token 预算而非墙钟时间，控制环境方差；
   - 引入“子任务完成率”“探索广度”“命令有效率”等细粒度指标，超越二元的 shell 成功率判断；
   - 人工分析全套执行轨迹分类失败原因，洞察深入。
5. **消融实验设计合理**：分别验证 Cache 和 Reviewer 的独立贡献，结论清晰可信。
6. **工程细节完备**：交互式 PTY 会话、数据流驱动的超时监控、MySQL 持久化等实现了面向真实部署的可操作性。
7. **对 LLM 局限性的诚实讨论**：包括统计偏差、暴力破解类任务不适合 LLM、GUI 交互缺失等，为后续方向提供了明确指引。

## 8. 不足与局限

1. **实验范围有限**：仅 10 个 HTB 靶机，且大多为 Linux/Web 类；Windows/AD 仅 2 个（且都为 Hard），结论向大规模企业网络的推广需谨慎。
2. **“完全自主”名不副实**：在 HTB-Interpreter 案例中依赖人工辅助密码破解（尽管排除于正式评估之外）；对需要暴力破解的现实场景仍高度依赖人工。
3. **可复现性存疑**：LLM 推理的随机性、HTB 靶机环境的动态变化、API 定价差异、token 化差异等使结果难以精确复现；部分基线（PentestGPT-V2）出现知识泄漏，可能影响对比公平性（尽管泄漏排除后对 MazeRunner 更有利）。
4. **无多模态能力**：无法处理需要 GUI 交互的任务，限制了浏览器和桌面类攻击场景的覆盖。
5. **安全边界定义不足**：如何定义“破坏性/侵入性”动作并设置审查机制，文中只有原则性描述，缺乏具体策略；对逃避检测、业务连续性等真实渗透要素未加处理。
6. **对已知漏洞的依赖**：系统不擅长零日漏洞发现；没有公开 exploit 时难以推进——将其定位为“任务编排器”而非“漏洞发现器”，缩小了应用范围。
7. **评估者偏差风险**：ground truth 由作者人工标注，失败分类靠人工审查，存在主观判断成分；且作者未报告标注者间一致性（inter-annotator agreement）。
8. **搜索空间困境未解决**：LLM 对常见攻击的统计偏好导致罕见路径的遗漏，作者承认这是深度与广度之间的固有权衡，未给出根治方案。
9. **环境差异性限制**：所有实验在本地 Kali Linux 服务器上运行，未测试分布式、高延迟或对抗性防御环境下的表现。
