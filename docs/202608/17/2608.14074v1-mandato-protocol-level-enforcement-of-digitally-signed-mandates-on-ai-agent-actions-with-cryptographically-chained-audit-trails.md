## 摘要
AI代理日益通过标准化工具调用协议（如模型上下文协议MCP）在外部系统上执行操作，然而目前尚无基础设施层将其行动约束在委托人可验证授权的范围内：授权逻辑存在于应用程序代码中，既未签名也无法独立审计，由此产生的日志缺乏证据价值。我们提出Mandato——一种治理代理，在协议级别对代理行动强制执行数字签名授权。授权（mandate）是一种机器可读、经密码学签名的授权工件，规定代理可以调用哪些工具、在何种参数约束和上下文条件下、持续多长时间以及代表谁执行操作；该代理对每次工具调用对照适用的授权链进行评估，实时阻止不符合要求的调用，并将每个决策——允许、拒绝及其证据——记录在仅可追加的哈希链审计日志中，该日志设计用于证据目的，并定期通过合格时间戳进行锚定。该授权刻意仿照民法中的授权委托制度设计，使工件对律师和审计员同样易读，而不仅限于工程师。我们给出了授权模型及其决策语义、作为MCP透明代理的参考架构（具有分离的决策点和执行点），以及该机制对欧盟《人工智能法案》第12条和第14条、GDPR问责制、NIS2和eIDAS 2的映射，包括通过合格信任服务提供商（QTSP）实现合格认证的路线图。我们还描述了参考系统的实现状态，以及涵盖执行开销、审计完整性和防篡改验证成本的定量评估计划。

## Abstract
AI agents increasingly act on external systems through standardized tool-calling protocols such as the Model Context Protocol (MCP), yet no infrastructure layer constrains their actions to what a principal has verifiably authorized: authorization logic lives in application code, is neither signed nor independently auditable, and the resulting logs lack evidentiary value. We present Mandato, a governance proxy that enforces digitally signed mandates on agent actions at the protocol level. A mandate is a machine-readable, cryptographically signed authorization artifact specifying which tools an agent may invoke, under which parameter constraints and contextual conditions, for how long, and on whose behalf; the proxy evaluates every tool call against the applicable mandate chain, blocks non-conforming calls in line, and records every decision -- permit, deny, and the evidence for each -- in an append-only, hash-chained audit log designed for evidentiary use and periodically anchored via qualified timestamps. The mandate is deliberately modeled on the civil-law institution of delegation of authority, making the artifact legible to lawyers and auditors, not only to engineers. We give the mandate model and its decision semantics, the reference architecture as an MCP-transparent proxy with separated decision and enforcement points, and a mapping of the mechanism onto EU AI Act Articles 12 and 14, GDPR accountability, NIS2, and eIDAS 2, including a roadmap to qualified attestation through Qualified Trust Service Providers (QTSPs). We describe the implementation status of the reference system and a quantitative evaluation plan covering enforcement overhead, audit completeness, and tamper-evidence verification cost.

# Mandato：基于数字签名的AI代理行动协议级强制与密码学链式审计追踪——论文总结

## 1. 核心问题与研究动机

**背景**：大语言模型（LLM）代理正从"生成文本"跨越到"执行行动"——通过标准化工具调用协议（如 Model Context Protocol, MCP）完成预订、支付、提交文件、签名、查询注册表、修改记录等操作。MCP 已成为事实上的互操作层，赋予代理对 MCP 服务器所暴露工具的统一访问能力。

**核心问题**：当前**不存在任何基础设施层**将代理行动约束在委托人（principal）已可验证授权的范围内。具体表现为三个结构性缺陷：

1. **授权不是工件（artifact）**：授权逻辑嵌入应用代码，无法独立于代码库被检查、版本化、签名、委托或撤销。
2. **执行不独立**：同一代码既做决策又做执行，提示注入（prompt-injection）或对齐失败的代理——或存在缺陷的集成——可绕过预期限制，且第三方无法验证限制是否被应用。
3. **日志不具证据价值**：普通应用日志可变、未签名、不完整，在争议、欧盟《人工智能法案》（AI Act）审计或 GDPR 数据保护调查中几乎毫无价值。

**监管压力**：EU AI Act 要求高风险 AI 系统自动记录事件（第12条）和有效人类监督（第14条）；GDPR 要求控制者"证明"合规（第5(2)、24条）而非仅实现合规；NIS2 将安全措施问责延伸到管理层；eIDAS 2 提供了合格签名、印章和时间戳工具箱——但缺少将这些法律工具连接到代理工具调用的基础设施环节。

## 2. 方法论：Mandato 的技术方案

### 2.1 核心思想

将**授权重新物化为头等公民的签名工件——mandate（授权书）**，并在**代理无法绕过的协议咽喉点**强制执行。Mandato 仿照民法中的委托授权制度（意大利民法第1703–1741条，代理以委托人名义并为委托人利益行事），使范围、委托、追认和撤销的语义对律师、审计员和记录管理者天然可理解。

### 2.2 授权模型（Mandate Model）

一个 mandate 是一个元组：
```
M = (id, P, A, Σ, Γ, V, D, σ_P)
```

- **id**：全局唯一标识符
- **P**：委托人（自然人或法人，绑定可验证身份——eIDAS 证书、组织印章或 EUDI 钱包凭证）
- **A**：代理（工作负载身份：密钥对、部署指纹、模型/版本标识）
- **Σ**（范围）：一组授权（grants），每个授权为 `g = (τ, Π, κ, q)`，其中 τ 为工具名或工具族（绑定到 MCP 服务器公告的工具列表）；Π 为参数约束集（来自**刻意封闭的非图灵完备约束语言**：相等、枚举集合、数值范围、已验证标识符字段上的字符串前缀、结构存在/缺失）；κ ∈ {auto, confirm, forbid} 为监督类别（直接执行/需同步人工确认/拒绝但仍记录）；q 为可选配额（速率或聚合限额）
- **Γ**（上下文条件）：约束环境而非调用本身——时间窗口、源部署身份、会话绑定、**目的绑定**（声明目的字符串写入每条日志记录以支持 GDPR 目的限制分析）
- **V = [t_nbf, t_exp]**：有效期窗口
- **D**：委托策略——规定代理是否可向下签发子授权、深度限制及收窄规则
- **σ_P**：委托人对所有前述字段的规范化序列化的数字签名（JAdES 或受限环境中 JWS）

### 2.3 关键机制

| 机制 | 说明 |
|---|---|
| **单调衰减（Monotone Attenuation）** | 子授权 M′ 仅当 Σ′⊆Σ、Γ′⊇Γ、V′⊆V 且监督类别不弱化（confirm 不能变为 auto）时有效；验证链上每个签名和每个衰减步骤 |
| **默认拒绝（Deny-by-Default）** | 缺少授权、链过期、签名不可验证、未知工具、越界约束均归于 DENY |
| **决策语义** | 确定性且**无 LLM 参与**：δ(c, M) = PERMIT（存在可适用且 κ=auto 的授权）/ ESCALATE（存在可适用且 κ=confirm 的授权）/ DENY（其他） |
| **撤销** | 委托人签名的撤销行为，引用授权 id，分发至执行点并记录；执行点若撤销视图陈旧则故障关闭 |
| **追认（Ratification）** | 委托人可追溯批准已记录的、被拒绝或升级的行动，产生签名记录改变行动的法律立场——历史通过追加而非编辑来纠正 |

### 2.4 参考架构：透明 MCP 代理

- **部署位置**：代理连接到 Mandato 代理（以为是工具服务器），Mandato 上行连接真实 MCP 服务器。这带来三个性质：**完备性**（所有工具发现/调用/结果均流经代理）、**不可绕过性**（上游服务器仅接受代理的工作负载身份 mTLS 会话）、**中立性**（代理和服务器零修改）。
- **PDP/PEP 分离**（遵循 XACML 模式）：执行点（内联拦截器）极简且故障关闭；决策点基于授权存储、撤销视图和配额计数器评估。升级（confirm）路由到人工监督控制台，挂起调用利用 MCP 任务语义，人工批准的是"针对授权的行动"而非原始 JSON 数据。
- **证据日志**：每条决策生成记录 `r_i = (t_i, c_i↓, M_i_ref, δ_i, π_i, h_i)`，其中 `h_i = H(h_{i-1} ∥ r_i_body)` 为链式哈希；敏感参数值使用**选择性哈希承诺**（GDPR 最小化措施）；定期检查点（Merkle 根）经 RFC 3161 时间戳或 eIDAS 合格时间戳/印章外部锚定；验证是独立操作，审计员无需信任操作者即可验证完整性和完整性。

### 2.5 威胁模型

**设计针对**：受攻陷/注入的代理（受 Σ 约束）；恶意工具服务器（结果被记录、服务器白名单+模式验证）；篡改操作者（外部锚定检测，但锚定前抑制是诚实局限）；委托人抵赖（委托人的合格签名反制）。**不在范围内**：允许调用内部的隐蔽信道、满足所有谓词的语义滥用——约束限制权力，而非判断。

## 7. 优点

- **法律语义对齐是突出亮点**：将授权工件建模为民法委托制度，使工程师、律师和审计员共享同一语义域，这是现有系统（macaroons、OAuth RAR、XACML、VC）未做到的。
- **架构设计稳健**：PDP/PEP 分离沿用 XACML 成熟模式；透明 MCP 代理定位带来完备性、不可绕过性和中立性三个强性质；默认拒绝和无 LLM 参与决策路径符合 Symbolic[Neuro] 的安全设计立场。
- **证据链设计完整**：哈希链 + Merkle 根检查点 + 外部锚定 + 独立验证，构成了从生成到审计验证的完整证据链路；选择性哈希承诺兼顾证据价值与数据最小化。
- **合规映射具体可操作**：逐条（article-by-article）映射至欧盟主要监管框架，并给出从基线到 QTSP 集成的清晰路线图（路线图被诚实标记为路线图而非已实现成就）。
- **工程规范程度高**：明确提及 170+ 编号需求（RF-/RNF-）、架构分解（ARCH-*）、22+ 关系表、22 个用例（UC-01–22）、里程碑路径 M0–M8.5 和公开跟踪的开放设计点（APERTO-01–06），体现了将治理系统当作严肃工程产品的态度。

## 8. 不足与局限

### 结构性局限（论文作者自述）
1. **约束权力而非能力**：被允许的调用仍可能是坏主意；约束语言不能替代委托人的判断义务。
2. **法律解读是对齐主张而非成熟定论**：mandate 作为委托行为的法律解读需法律学术和判例法验证；跨学科评估本身就是未来工作。
3. **篡改证据有窗口期**：锚定方案在检查点间隔内是防篡改证据（tamper-evident）而非防篡改（tamper-proof）；共签和缩短间隔以成本换暴露，需定量刻画该权衡。
4. **联邦/多代理部署未解决**：跨组织委托（不同委托人的配额冲突、跨域撤销传播）仅支持单权威情形。

### 实验相关局限
5. **零实证结果**：所有评估均为计划；执行开销的接受标准（p95 ≤ 5%）虽有明确阈值，但未说明负载模型、工具执行时间分布等前提条件。
6. **基准缺失**：未与现有方案（如简单的应用内授权、OAuth 作用域、XACML 策略服务器）做对比，无法判断 Mandato 的增量价值是否值得其部署复杂性。
7. **人体工学评估存在偏差风险**：升级放弃率依赖试点用户群体；论文未说明试点规模和选择标准。
8. **威胁模型有明确边界**：不防御允许调用内的隐蔽信道和满足所有谓词的语义滥用——对于高风险场景（如金融支付），这些恰是攻击者最可能利用的漏洞类别。
9. **表达式语言表达力未知**：封闭约束语言能覆盖多少真实授权需求，必须待表达力审计完成后方可判断；IN 表达力不足可能导致实践中的大量逃生舱口，削弱模型的可审计性主张。

## 总结

Mandato 是一项定位精准的治理基础设施提案：将代理授权从"嵌入代码的隐式状态"转变为"签名的显式法律工件"，并在协议级强制执行、以链式审计日志产生证据。其最大贡献在于**搭建了从技术机制到法律制度的桥梁**——每个技术设计决策都能对应到具体的法律义务和既有法律行为。但作为早期系统论文，其价值目前主要体现在**设计合理性**而非**实证有效性**上；5 组明确定义的评估计划是诚实且可证伪的赌注，结果尚待揭晓。对关心 AI 治理、可问责代理系统和欧盟 AI 合规的读者，这是一篇值得关注的有力提案。
