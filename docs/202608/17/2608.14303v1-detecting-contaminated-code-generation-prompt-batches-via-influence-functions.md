## 摘要
大型语言模型（LLMs）越来越多地用于代码生成，但它们仍然容易受到诱导生成不安全实现的提示的攻击。现有的防御方法通常依赖于预定义威胁模型或已知漏洞模式，这限制了对新型攻击的有效性。我们提出了CodeSIFT，一种与威胁模型无关的检测方法，利用影响函数来识别引起异常模型行为的提示批次。CodeSIFT不是检测特定漏洞，而是衡量生成代码的参数空间影响，并使用统计检验来确定候选提示集是否偏离良性参考分布。为了评估我们的方法，我们引入了两个涵盖各种漏洞的基准数据集。我们在三个参数量从3B到7B的开源代码LLM上评估了CodeSIFT，在中高注入率下取得了高达0.98的AUROC分数，同时保持了良好校准的假阳性率，并大幅优于静态分析基线。这些结果表明，基于影响函数的检测是识别恶意代码生成提示的一个有前景的方向，无需对潜在攻击类别有先验知识。

## Abstract
Large language models (LLMs) are increasingly used for code generation, yet they remain vulnerable to prompts that elicit insecure implementations. Existing defenses typically rely on predefined threat models or known vulnerability patterns, limiting their effectiveness against novel attacks. We propose CodeSIFT, a threat-model-agnostic detection method that leverages influence functions to identify batches of prompts that induce anomalous model behavior. Rather than detecting specific vulnerabilities, CodeSIFT measures the parameter-space influence of generated code and uses a statistical test to determine whether a candidate prompt set deviates from a benign reference distribution. To evaluate our approach, we introduce two benchmark datasets covering a variety of vulnerabilities. We evaluate CodeSIFT on three open-weight code LLMs ranging from 3B to 7B parameters, achieving AUROC scores of up to 0.98 at moderate-to-high injection rates, while maintaining well-calibrated false positive rates and substantially outperforming static analysis baselines. These results suggest that influence-function-based detection is a promising direction for identifying malicious code-generation prompts without requiring prior knowledge of the underlying attack class.

## 1. 核心问题与整体含义（动机与背景）

- **核心问题**：大型语言模型（LLM）在代码生成场景中容易被恶意构造的提示（prompt）诱导，生成包含安全漏洞的不安全代码（如缺失授权检查、未净化查询等）。此类"诱导错误"不触发常规的有害内容过滤器，构成现实的安全威胁。
- **现有防御的局限**：
  - 静态分析器（Bandit、Semgrep）和污点追踪依赖**已知漏洞模式目录**，对目录之外的变体和新型攻击失效；
  - 基于签名和规则的提示侧过滤器面临相同局限；
  - 现有的梯度/激活检测器主要针对越狱（jailbreak）和提示注入，不适用于过滤"诱导特定错误实现选择"的恶意代码生成提示。
- **论文的核心洞见**：将问题重新定义为**批次级统计检测**——给定一组候选提示批次，判断其是否"被污染"（包含恶意提示），**无需预先了解任何具体漏洞类别**。其做法是刻画模型正常（良性）行为的内部参数统计特征，再检验新提示批次的诱导行为是否偏离这一常态。

## 2. 方法论（CodeSIFT）

> CodeSIFT = **Co**de **S**tatistical **I**nfluence-**F**unction **T**est

- **核心概念：影响函数（Influence Functions, IF）**：
  - 对每个输入提示 z，定义其**提示影响分数** IFₚ,ε(z) = E[‖θ̂ − r̂_{ẑ,lin}(ε)‖ₚ]，其中 ẑ ~ f(z, θ̂) 是从模型中采样的生成响应；
  - 其理论依据是：该量近似 **近端 Bregman 响应函数（PBRF）**，衡量"以权重 ε 将响应 ẑ 加入训练目标时，模型参数需移动多少才能同时拟合该样本并保持原有预测行为"；
  - 恶意提示诱导的响应与良性训练分布不一致，因此对应的参数空间影响力更大。
- **技术实现流程（Algorithm 1）**：
  1. **曲率预计算**：在曲率数据集 Dc（取自 The Stack v2 代码语料库）上，计算各 MLP 投影的 K-FAC 稠密因子 Aⱼ、Gⱼ（梯度 Gram 矩阵估计）；
  2. **影响分数计算**：对每个候选和参考提示，采样 N 个生成响应，计算预处理梯度并求和得到 δ⁽ⁿ⁾，平均后得到 IF 分数；
  3. **统计检验**：对候选集 D 和良性参考集 D\* 的 IF 分数运行 **Welch 单侧双样本 t 检验**，p 值低于阈值 α 则判定批次被污染。
- **关键简化（与标准 K-FAC/EK-FAC 相比）**：
  - 省略特征值校正（不做 EK-FAC 的额外曲率数据遍历）；
  - **单侧预处理**：仅保留隐藏维度 h 对应的 Kronecker 因子，丢弃更大的 d_ffn 维度因子，将求逆成本从 O(d_ffn³) 降至 O(h³)；
  - 直接从归一化的梯度 Gram 矩阵估计因子，避免缓冲中间激活。
- **效率**：Hessian 逆近似与输入无关可一次性预计算，每个提示的影响分数估计仅需 O(mN) 次操作（m 为参数量，N 为采样数）。
- **无威胁模型假设**：整个方法不枚举漏洞类型，只比较"良性参考"与"候选批次"之间的行为差异。

## 3. 实验设计

- **基准数据集（自建，800 条 Python 记录）**：

  - 每条记录包含自然语言补全指令 + 带标记空缺的 Python 骨架，标记（# TODO: 等）由固定循环规则分配，与标签无关；
  - **曲率数据集**：从 The Stack v2 中均匀采样 100 条提示。
- **评估模型（3 个代码 LLM）**：
  - Granite-3B-Code-Instruct-2K（IBM，3B 参数）
  - DeepSeek-Coder-6.7B-Instruct（DeepSeek，6.7B 参数）
  - Qwen2.5-Coder-7B-Instruct（阿里，7B 参数）
- **基线方法（3 个静态分析器）**：
  - **Bandit**：标准 Python 静态安全 linter（AST 模式匹配）；
  - **Semgrep**：配开源通用 Python Web 规则包的静态分析工具；
  - **AST Taint Tracker**：作者自实现的简单污点追踪器（从 Flask request 源到安全敏感汇）。
  - 所有基线在相同的 t 检验框架下比较，保持测试流程一致，仅改变底层信号。
- **主要评估指标**：AUROC（随注入率变化的曲线）、经验假阳性率 vs 名义显著性水平 α 的校准曲线。

## 6. 主要结论与发现

- **CodeSIFT 检测性能**：
  - 在所有模型-数据集组合下，AUROC 随注入率**单调提升**；
  - AuthSec 上，最低注入率时 AUROC 达 0.6–0.85，注入率 40–50% 时饱和至接近 1.0；
  - InfraCloud 上（更具挑战性），AUROC 峰值 0.88–0.98；
  - **假阳性率校准良好**：经验 FPR 紧密跟随名义 α（0.01–0.09），未出现系统性过度/欠拒绝。
- **基线的失败模式**：静态基线性能**跨模型不一致**——Bandit 在 DeepSeek 上接近 CodeSIFT，在 Granite/Qwen 上接近随机；Semgrep 与 AST Taint Tracker 在多种场景下 AUROC < 0.5，即与真实标签**反相关**（越检测越错）。
- **关键洞察**：参数空间影响力信号跨模型家族迁移，而表面模式匹配不迁移；检测无需预知漏洞类别。

## 7. 优点

1. **威胁模型无关**：不枚举具体漏洞模式，能检测未知/新型攻击（这是相对静态分析的本质性突破）；
2. **理论联系扎实**：将影响函数解释与 PBRF 建立联系，为"参数偏移"作为异常信号提供理论支撑；
3. **计算效率高**：K-FAC 稠密因子单次预计算 + O(mN) 每提示复杂度，具备实际可行性；单侧简化大幅降低求逆成本；
4. **实验严谨**：控制了领域分布与标签正交、标记无信息性；采用一致的统计检验框架对比基线；报告校准曲线而非单点结果；
5. **跨模型泛化证据**：三个不同架构、不同组织、不同规模的模型均取得一致结果，增强了结论的可靠性；
6. **样本效率好**：每提示仅需 5 次采样即可达到较好效果，候选集 20–30 个提示即可接近上限 AUROC。

## 8. 不足与局限

1. **批次级检测而非单提示定位**：CodeSIFT 只能判断"整批是否被污染"，无法指出批次内具体哪个提示是恶意的（作者在讨论中承认这是自然下一步）；
2. **模型规模覆盖有限**：实验仅覆盖 3B–7B 参数模型，作者提到先前的 52B 影响函数工作暗示可扩展性，但本文未验证更大模型上的表现；
3. **仅限 Python 与有限漏洞家族**：基准数据只覆盖 Python 和两个应用域（AuthSec、InfraCloud），跨语言/跨攻击面的通用性未验证；
4. **依赖获取难度**：需要与模型预训练分布近似同分布的曲率数据集（Dc），而多数开放权重模型的预训练语料不公开，The Stack v2 的近似是否足够好依赖于经验验证；
5. **K-FAC 简化可能损失精度**：省略特征值校正、单侧预处理和梯度 Gram 估计是计算可行性与保真度之间的权衡，这些简化对分数质量的具体影响未做消融量化；
6. **Welch t 检验的分布假设**：IF 分数并非严格正态，t 检验的小样本性质（尤其候选集较小时，作者也承认难例情境）有待更详细的鲁棒性分析；
7. **未报告运行时间**：缺少各阶段（曲率预计算、分数估计、检验）的具体耗时数据，难以评估实际部署的实时性；
8. **静态度量**：检测依赖单个时间点的生成批次，未涉及随时间变化、自适应攻击者或动态对抗场景。
