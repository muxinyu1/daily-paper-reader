## 摘要
基于LLM的智能体可以代表用户访问云服务、调用工具或调用其他智能体。在会话开始时，智能体的权限已设置但保持静态，每个请求独立评估，不考虑先前的操作。在其权限范围内，智能体可能做出与委托任务相反的行为，将单独允许的操作组合成被禁止的结果，或者将权限委托给没有限制的子智能体。提示注入只有在智能体有权执行此类操作时才构成风险；因此，这是一个授权架构问题，而不仅仅是模型问题。智能体主体链（APC）跟踪从一个主体到下一个主体的委托权限。APC使用六种授权检查，根据累积的会话状态评估每个请求。APC向前传递并限制委托范围和预算。利用组合闭包，APC检查请求与先前操作，以防止被禁止的组合，并在模型之外执行决策。我们证明了APC实现的爆炸半径单调性和组合健全性；组合健全性仅限于在完整限制集和串行准入下的被禁止组合。我们评估了3,154个实例，包括InjecAgent、AgentDojo和ASB。我们通过插入真实攻击调用（在第一个合法工具调用之后）来独立于模型行为测试APC。AgentDojo的泄露在所有四个领域从75-100%下降到0%；APC阻止了所有544个InjecAgent数据窃取案例。意图绑定将破坏从38.6%降至4.0%，操纵从90.5%降至12.1%。在空闲主机上，授权延迟在第99百分位为0.24毫秒；在949个AgentDojo任务注入对中，效用分别低8.6和13.9个百分点。实现、评估工具和数据是公开可用的。

## Abstract
LLM-based agents can act on behalf of a user to access cloud services, call tools, or invoke agents. At session start, the agent's permissions are set but remain static, and each request is evaluated independently, without considering prior actions. Within its permissions, an agent may act contrary to the delegated task, combine individually permitted actions into a prohibited outcome, or delegate authority to a sub-agent without limiting it. A prompt injection poses a risk only if the agent has authority to perform such actions; this is therefore a problem of authorization architecture, not just the model. The Agentic Principal Chain (APC) tracks delegated authority from one principal to the next. APC evaluates each request against the accumulated session state using six authorization checks. APC carries forward and restricts delegated scope and budgets. Using composition closure, APC checks requests against prior actions to prevent prohibited combinations and enforces the decision outside the model. We prove Blast Radius Monotonicity and Composition Soundness for APC implementations; Composition Soundness is limited to prohibited combinations under a complete restriction set and serialized admission. We evaluated 3,154 instances including InjecAgent, AgentDojo, and ASB. Our compromised-model evaluation tests APC independently of model behavior by inserting the ground-truth attack call after the first legitimate tool call. AgentDojo exfiltration fell from 75-100% to 0% across all four domains; APC blocked all 544 InjecAgent data-stealing cases. Intent binding reduced destruction from 38.6% to 4.0% and manipulation from 90.5% to 12.1%. Authorization latency was 0.24 ms at the 99th percentile on an idle host; across 949 AgentDojo task-injection pairs, utility was 8.6 and 13.9 percentage points lower in the two settings. Implementation, evaluation tools, and data are publicly available.

### 1. 论文的核心问题与整体含义

**研究动机与背景**：随着基于大语言模型（LLM）的智能体系统在企业中广泛部署，智能体能够代表用户访问云服务、调用工具、委托子智能体执行任务，并产生不可逆的后果。然而，现有的访问控制机制存在三个根本性缺陷：

- **权限静态化**：会话开始时设定的权限在整个会话中保持不变，无法适应运行时动态演化的执行路径；
- **逐请求独立评估**：每个请求被独立审批，不考虑会话中先前操作的历史状态；
- **委托范围不受限**：智能体可将权限委托给子智能体而不加约束，且委托链路缺乏逐跳的权限衰减机制。

**核心论点**：论文提出一个关键主张——**提示注入（prompt injection）的安全后果本质上是一个授权架构问题，而非单纯的模型鲁棒性问题**。一个没有外发通信工具权限的智能体，无论被注入什么内容都无法窃取数据；反之，如果智能体有权限执行某项操作，那么模型是否足够"抵抗"注入变得次要。因此，问题的关键在于"模型在被操纵时被授权做什么"，而不是"模型是否会遵循恶意指令"。

**三个结构性观察**：
- 模型必须被排除在自身信任边界之外——"执行前请确认"这类提示指令可被覆盖或忽略，必须由基础设施层的策略执行点（PEP）强制执行；
- 逐动作授权在结构上不足——授权读取机密文档和发送外部邮件的智能体可组合两者实现数据外泄，而任何单个权限都不违反规则，这是动作组合层面的"困惑代理"（confused deputy）问题；
- 多智能体系统必须假设存在被攻破的组件——每条委托链路都是新的攻击面，爆炸半径必须由架构约束。

### 2. 论文提出的方法论：核心思想与关键技术

论文提出**Agentic Principal Chain（APC）模型**，一个会话级（session-scoped）的授权状态层，沿委托链路跟踪并收缩授权范围，在模型运行时之外由基础设施强制执行。

**核心抽象**：
- **授权范围（Scope）**：\(S = (R, A, D, X)\)，其中 R 为允许资源、A 为允许动作类型、D 为允许数据分类、X 为禁止的动作组合集（禁止组合闭包）。委托时两个范围通过"meet"运算相交，结果只会更窄：\(S_1 ⊓ S_2 = (R_1∩R_2, A_1∩A_2, D_1∩D_2, X_1∪X_2)\)，限制只能累积，下游主体不能移除。
- **委托链（Principal Chain）**：\(C = ⟨p_0, p_1, ..., p_n⟩\)，从人类用户到编排者到子智能体到工具，基础设施在每个跳点计算范围收窄 \(S(p_i) = S(p_{i-1}) ⊓ S_{role}(p_i)\)，而非由智能体自行决定。
- **委托预算（Delegation Budget）**：六个上限——委托深度、累计爆炸半径、不可逆效果、敏感度类别、跨域组合、计算成本，只能递减。
- **会话意图（Session Intent）**：由会话发起者在创建签名信封时预先声明的意图规范 Ψ，包含任务目标、允许的资源模式、允许的动作序列、负面约束等。意图收窄但绝不拓宽授权范围。
- **先行动作状态（Prior-Action State）**：基础设施维护的会话已执行动作类型集合及有序历史，模型输出无法重置或伪造。

**六项授权检查（判定条件）**——每项提议动作须全部通过：

- **C1 身份绑定**：运行时执行者必须绑定到委托链中可验证的身份；
- **C2 范围衰减与组合闭包**：动作在收窄范围内；动作不与先前动作构成被禁止的组合；满足委托预算上限；
- **C3 上下文与状态绑定**：绑定特定任务实例、策略版本、参数上下文，防止跨会话重放；
- **C4 审批绑定**：计算影响分数 \(I(a) = w_ρ·ρ(a) + w_β·Bl(a) + w_σ·Se(a)\)，超过阈值 θ 的需要一次性、哈希绑定的审批令牌；
- **C5 证据提交**：执行前验证证据存储可达，以 SHA-256 哈希链实现防篡改审计；
- **C6 意图绑定**：对照预先声明的意图规范检查，负面约束优先于一切权限。

**关键公式与非形式化说明**：

- **定理4.6（爆炸半径单调性）**：对于任何委托链，每一步的**最大可达爆炸半径**都是非递增的：\(\forall i: BR_{max}(p_i) ⊆ BR_{max}(p_{i-1})\)。证明基于三要素：范围收窄使资源集缩小、预算上限非递增、预算消耗沿链累积只增不减。该性质保证：若攻击者在深度 k 处攻破子智能体，损害上限被该位置的当前范围与剩余预算所限定。
- **定理4.7（组合健全性）**：给定完备的有效限制集 \(X_{eff}\) 和串行准入机制，**没有任何可准入的动作序列能产生被禁止的结果**。证明通过反证法：若可准入序列产生被禁止结果，则其中必然出现限制集中的某个被禁止动作对，而第二个动作在评估时检查到先前动作已在已执行集合中，必然被拒绝。
- **命题4.2（有序 k 元组健全性）**：扩展到需要三个及以上动作类型的攻击（如 read → write → send_internal 的分阶段外泄），通过有序子序列匹配来拦截，而这类攻击可以绕过两两组合限制。
- **命题4.1（意图细化）**：意图只限制、绝不拓宽授权范围，因为信封创建时验证了 \(R_Ψ ⊆ R(S(p_i))\) 且 \(A_Ψ ⊆ A(S(p_i))\)。

**架构部署**：PEP 实现为工具网关或 MCP 网关，位于智能体运行时和后端之间，是唯一的动作执行瓶颈，模型无法绕过。PDP 评估六条件，PEP 依据判定门控执行并提交证据。若证据存储不可达，动作被拒绝（fail-closed）。

### 6. 论文的主要结论与发现

1. **提示注入的安全后果主要是授权架构问题**，而非单纯的模型鲁棒性问题。无法组合外泄所需动作的智能体，对试图外泄的注入攻击本身不构成脆弱性——无论模型行为如何。
2. **组合闭包是一种有效的授权原语**：在完备限制集下，任何可准入动作序列都不会产生被禁止的结果；k元组扩展可捕获多步外泄（如 read → write → send_internal ），这类攻击能绕过两两限制。
3. **爆炸半径单调性成立且可证明**：暴破半径沿委托链非递增，攻破深度k的子智能体最多只能造成该位置的受限损害。
4. **基础设施层强制有效且开销极低**：完整六条件判定在空闲主机上 p50 0.05ms、p99 0.24ms（移动级CPU），99个委托链场景全部产生预期结果。
5. **安全与效用存在可量化的权衡**：交互模式以−8.6pp的效用代价换取0%的外泄成功率（四域全部），匹配协议下与Progent相当（+1.6pp，在±2pp等价阈值内）。
6. **残余风险明确且可分类**：主要集中于粗粒度动作分类下的意图重叠（14例）、缺失组合限制对（4例），以及单动作、参数级攻击（60.4%的InjecAgent直接危害残余）——后者明确位于APC设计边界之外。

### 7. 优点

**方法论方面**：
- **形式化证明先行**：爆炸半径单调性和组合健全性是对委托代数（delegation algebra）的性质证明，而非对特定引擎的验证——对任何忠实于APC语义的实现都成立，这为实际部署提供了结构性保证而非经验性信心；
- **模型排除在信任边界之外**：所有关键决策均由基础设施实现，模型输出只能提议动作，不能修改授权状态；
- **组合闭包作为正式原语**：这是经典授权模型（RBAC、ABAC、OAuth）中不存在的约束类型，填补了动作序列级安全的形式化空白；
- **多机制分层设计**：六条件分为结构层（Tier 1）、配置层（Tier 2）、运维层（Tier 3），明确了各保证的依赖条件与局限；
- **damage containment 的架构理念**：默认采用"假设被攻破"的安全姿态，通过结构保证而非模型鲁棒性来约束损害。

**实验方面**:
- **受损模型评估方法**是一种方法论创新：通过注入真实攻击调用，将基础设施安全能力与模型抗操纵能力完全解耦，可直接证明"即使模型完全被攻破，也能阻止外泄"；
- **与Progent的匹配协议比较**增加了外部效度，且设置了预定义等价阈值，比较方式透明；
- **残余案例的重新审计**：对ASB的2个幸存工具类型进行了独立的语义审计，追溯至动作分类粒度问题而非机制缺陷，体现了分析严谨性；
- **测量环境明确、可复现**：报告了完整的测量方法、环境、变异范围，并提供了可重新运行的脚本和已提交的结果文件。

### 8. 不足与局限

**形式化层面**:
- **定理4.7的完备性依赖**：组合健全性依赖限制集 \(X_{eff}\) 的完备性——这本身无法由机制保证，而是策略编写者的责任。消融实验显示移除一个限制对即可使数据窃取ASR从0%升至39.9%；
- **串行准入假设**：并发子智能体要求PEP对组合检查串行化以避免TOCTOU，实际部署中高性能并发场景可能需要额外机制；
- **定理未经机器验证**：作者明确指出定理尚未机械化证明（machine-checked），属于未来工作。

**实验层面**:
- **合成基准的局限**：所有基准（InjecAgent、ASB、AgentDojo）均为学术合成环境，未提供生产部署数据；
- **模型覆盖有限**：效用评估仅使用Claude Sonnet 4.6，未测试其他厂商模型或开源模型的差异；
- **受损模型模拟较简单**：在第一个合法调用后注入攻击调用，不模拟多轮交错恶意/合法调用的复杂对抗、自适应性学习等更精细的对手行为；
- **自适应攻击为自设计**：未经外部红队无偏评估，存在评估者偏差风险。

**架构层面**:
- **动作分类粒度是根本局限**：\(μ: Tools → C\) 的分类映射依赖专家判断，不同团队可能得出不同限制集；分类过粗导致意图重叠误判（如表9中 create_calendar_event 归类为write导致78%残余攻击属此类）；
- **跨会话攻击无法拦截**：组合状态是会话内的（T3），跨会话拆分攻击（session splitting）被明确承认设计上放行；
- **单主体折中假设**：假设单一主体被折中；多主体同时折中（k≥2）时，残余风险集中于跨会话协调问题；
- **单动作参数级攻击在边界之外**：对授权范围内单动作的参数滥用（如删除一个虽授权但错误的文件）需要参数级验证，APC不提供此能力。

**效用层面**:
- 严格模式在部分域有较高效用损失（如银行业务−18.8pp、Slack−16.5pp）；
- 效用实验中报告的是均值与标准差而非分布细节，不同域间差异较大（旅行域在交互模式下甚至略高于基线+0.2pp，而银行业务−10.0pp）。
