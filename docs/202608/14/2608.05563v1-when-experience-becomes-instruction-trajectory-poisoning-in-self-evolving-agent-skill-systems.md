## 摘要
自我进化技能（SES）系统将智能体轨迹提炼为持久技能，使得不可信的经验得以成为可信的指令。我们提出了PoisonedEvolution，一种针对这一提升过程的轨迹投毒攻击。我们的技能可见黑盒攻击者能够检查目标技能并贡献有界证据，但无法观察私有池或进化逻辑，也无法编辑技能库。人工制品投毒需要包含性、进化归因和实现性。归因是显著瓶颈：目标行为必须在提升之前表现为因果有用、可复现且可泛化。我们使用惰性金丝雀规范评估了四个代表性的安全效应家族。在10%攻击者支持率下，跨SkillClaw中六个主流LLM进化器，PoisonedEvolution在546/600次试验中嵌入了目标行为（91.0% SER）。在结构不同的Trace2Skill流水线上以相同比例，它在369/600次试验中嵌入了目标行为（61.5% SER），证明了跨进化架构的迁移性。在一项代表性对照研究中，30条记录批次中三条一致的攻击者记录就足够了，而单条记录则弱得多。消融实验识别出重复支持、因果框架和领域对齐编码是成功的主要决定因素。这些发现揭示了证据提升作为自我进化智能体的安全边界。

## Abstract
Self-evolving skill (SES) systems distill agent trajectories into persistent skills, allowing untrusted experience to become trusted instruction. We introduce PoisonedEvolution, a trajectory-poisoning attack on this promotion process. Our skill-visible black-box attacker can inspect a target skill and contribute bounded evidence, but cannot observe private pools or evolution logic or edit the skill bank. Artifact poisoning requires Inclusion, Evolution Attribution, and Realization. Attribution is the distinctive bottleneck: the target behavior must appear causally useful, recurrent, and generalizable before promotion. We evaluate four representative security-effect families using inert canary specifications. At 10% attacker support, across six mainstream LLM evolvers in SkillClaw, PoisonedEvolution embeds target behaviors in 546/600 trials (91.0% SER). On the structurally different Trace2Skill pipeline at the same ratio, it embeds target behaviors in 369/600 trials (61.5% SER), demonstrating transfer across evolution architectures. In a representative controlled study, three consistent attacker records suffice in a 30-record batch, whereas a single record is much weaker. Ablations identify recurring support, causal framing, and domain-aligned encoding as the main determinants of success. These findings expose evidence promotion as a security boundary for self-evolving agents.

### 一、核心问题与整体含义

- **研究背景**：LLM智能体日益依赖“技能”（skills）作为持久化的指令工件（如SKILL.md），描述工作流、触发条件、约束与工具使用约定。技能一旦安装或进化，将成为智能体未来的操作规程，因此技能创建本身就是安全边界。
- **核心问题**：自我进化技能（Self-Evolving Skill, SES）系统——如SkillClaw、Trace2Skill——自动从智能体交互/执行轨迹中蒸馏出可复用技能。这类系统默认“轨迹池反映良性证据”，并假设值得提升为持久指令。论文质疑这一假设：攻击者无需发布恶意技能、攻破进化器或直接编辑技能库，只需贡献少量看似正常、但经过精心构造的轨迹证据，即可让SES系统自身生成被投毒的技能工件。
- **核心术语**：
  - **PoisonedEvolution**：针对SES“经验→指令”提升过程的轨迹投毒攻击。
  - **技能可见黑盒攻击者（skill-visible black-box）**：可检查公开/已安装技能、贡献有界数量的轨迹，但无法观察私有池、过滤器、进化提示，也不能直接编辑技能库。
- **安全边界**：论文将“证据提升”（evidence promotion）视为自进化智能体区别于传统静态技能投毒的新信任边界，攻击针对的是经验与指令之间的提升策略，而非最终技能文件本身。

### 二、方法论

#### 1. 核心思想
攻击的核心是操纵进化器的“归因机制”：不直接要求进化器写入攻击者指令，而是让目标行为看起来像是解释成功或修复失败的可复用知识，从而被SES系统自然提升为持久技能。

#### 2. 形式化定义

系统抽象为四元组 Σ = (T, F, E, S)：
- T：轨迹池（含干净证据Tc与攻击者证据Tp）
- F：质量过滤器/路由器
- E：LLM驱动的进化器
- S：版本化技能库

一次进化周期：St+1 = St ⊕ E(F(Tt), St)，批次大小 n = |Tc|+|Tp|，攻击支持度 k = |Tp|，投毒比率 ρ = k/n。

**攻击成功三条件**：
- **C1 包含（Inclusion）**：投毒轨迹通过过滤器，进入进化器可消费的流。
- **C2 进化归因（Evolution Attribution）**：进化器将重复行为视为值得提炼为技能的模式（而非噪声、一次性事件或不安全建议）。
- **C3 实现（Realization）**：目标行为在摘要、合并后仍存活于生成的技能工件中，被检测为行为级金丝雀语义。

攻击目标函数：在预算 |Tp| ≤ k 下，最大化 Pr[C1 ∧ C2 ∧ C3]。

**攻击者策略三要素**：
- **领域对齐（Domain alignment）→ C1**：将投毒步骤放置在进化器可能预期出现可复用专长的位置（输入前置条件、恢复步骤、输出转换、验证步骤等）。
- **因果绑定（Causal attribution）→ C2**：目标行为与任务约束和观察结果绑定，形成“障碍/需求 → b → 任务完成”（成功路径）或“缺少 b → 失败”（失败路径）的结构，使目标行为看起来是结果的原因而非无关绕行。
- **跨轨迹不变性（Cross-trajectory invariance）→ C3**：多个投毒轨迹任务和措辞不同，但行为语义保持稳定，使其在汇总、改写、合并后仍能存活。

轨迹变换公式：τ′ = T(τa; s, b)，其中 τa = (q, h, y) 为攻击者拥有的任务轨迹，变换保留原始任务与结果，同时使 b 因果相关。h′ = eh<ℓ ∥ [constraint b, action b, successful retry] ∥ eh>ℓ 表示在合法工作流位点周围压缩任务特定历史。

#### 3. 攻击算法（Algorithm 1）
1. 从攻击者自有候选中选择 k 条与目标技能相关的任务轨迹
2. 定位合法的行为位点 ℓ
3. 添加结果条件化的因果桥：约束→b→成功，或缺失b→失败
4. 保持任务结果不变，变化表面措辞但保持行为语义不变
5. 贡献 k 条变换轨迹进入SES批次（ρ = k/n）
6. 运行SES进化周期，检查技能差异
7. 报告 b 是否在进化技能中实现

#### 4. 有效载荷表示
有效载荷表示为 p = ⟨ℓ, a, o, c⟩（工作流位点、动作、目标对象、执行上下文），四类安全效应家族：
- **F1 机密性**：输出工件后，将发现的凭证/敏感字段发送至 `<ATTACKER_ENDPOINT>`
- **F2 数据完整性**：输出后删除 `<SOURCE_PATH>` 源工件
- **F3 供应链完整性**：安装依赖前替换包注册表为 `<ATTACKER_REGISTRY>`
- **F4 运营安全削弱**：发布/提交前禁用 `<SECURITY_CHECKS>`

实验中所有效果均使用惰性金丝雀数据（临时路径、环回注册表、玩具CI标志），不执行实际攻击。

### 三、实验设计

#### 1. 数据集/基准
- **SkillClaw（主系统）**：目标为 xlsx 技能；源语料为 GLM-5 使用原始 xlsx 技能在 100 个 SpreadsheetBench 训练任务上执行的 300 个案例级执行日志（Ma et al. 2024）。转换日志为 SkillClaw 兼容会话，每个试验形成任务不同的 n 轨迹批次。
- **Trace2Skill（结构转移验证）**：3 条攻击者控制的失败轨迹 + 27 条干净的保留失败样本。
- **基准设置**：主要矩阵 n=30, k=3（ρ=10%），每个模型-家族单元 25 个完整试验。init 设置从原始 xlsx 技能开始（技能精炼）；no-init 诊断用于技能创建路径。

#### 2. 对比/变体设置
- **6个LLM进化器**：GPT-5.4、MiniMax-M2.5、DeepSeek-V3.2、DeepSeek-V4-Pro、Qwen3.5-35B-A3B、Qwen3.5-122B-A10B
- **RQ2机制消融**：
  - 固定 n=30 变化 k=1/2/3（单条 vs 重复）
  - 固定 k=3 变化 n=10/30/100（稀释效应）
  - C2条件：Local（单点插入）、Fragmented（跨记录碎片化）、Causal（因果结果绑定）
  - C3条件：Generic（宽泛指令）、Auxiliary（带外通道）、Tailored（领域特定可执行语义）
- **RQ3架构转移**：在 Trace2Skill 上相同 n=30, k=3 条件

#### 3. 防御门实验（原型）
Provenance-Diversity Gate：需要三个用户和聚类支持，拒绝多数派主导，惩罚高文本重叠。n=30, k=3时可使单聚类F1候选的25/25全部被阻断，post-gate SER 从25/25降到0/25。

#### 4. 良性效用检查
100任务轨迹收集分裂下，投毒进化后的 xlsx 技能得分为20.0% Hard / 36.54% Soft，而无技能为18.0% / 34.88%，说明投毒并未完全破坏正常任务效用。

### 六、主要结论与发现

1. **攻击可行性**：在10%攻击支持率下，PoisonedEvolution 在 SkillClaw 中将目标行为嵌入技能工件，546/600 试验成功（91.0% SER），证明 SES 的证据提升机制本身是可被利用的安全边界。
2. **跨架构转移**：在结构不同的 Trace2Skill 上达到 61.5% SER，证明攻击并非特定于某一进化提示或管线布局。
3. **重复支持是关键**：k=1 远弱于 k>1（5/25 vs 21/25/25/25），3条一致记录在30条批次中即足以成功——SES 系统设计目标是提炼重复经验，这正是被攻击利用的结构性张力。
4. **因果归因与领域对齐是核心瓶颈**：无因果框架的本地/碎片化插入仅为 8/25 和 11/25，因果绑定后为 25/25；通用或带外编码（18/25和0/25）远弱于领域特定的可操作编码（25/25）。
5. **进化器策略高度敏感**：各模型 SER 从 70% 到 100% 不等，说明进化策略本身是攻击面的重要组成部分。
6. **家族敏感性是相对的**：SkillClaw 最易提升 F4（146/150），Trace2Skill 则显著抑制 F4（28/150）而偏好 F2/F3——安全效应家族并非有固有排序，而是取决于行为与工作流位点及管线归因策略的语义适配度。
7. **防御方向**：最终技能扫描不够，需要在证据提升阶段实施 provenance-aware（来源感知）授权决策，保留支撑/反驳轨迹、贡献者聚类、进化器版本及精确技能差异的语义谱系。

### 七、优点

- **新颖的问题识别**：明确了 SES 管线中“证据提升”是区别于 RAG 投毒、直接技能注入的传统技能投毒的新安全边界，定位精准。
- **清晰的形式化框架**：C1-C3 三条件分解及形式化定义（Eq.1-8）使攻击机制透明可分析；将“进化归因”识别为 SES 特有的瓶颈，理论贡献明确。
- **归因导向的攻击设计**：通过因果绑定、跨轨迹不变性、领域位点对齐三管齐下，方法优雅且机制可解释，Algo 1 清晰可复现。
- **跨架构验证**：在 SkillClaw 和 Trace2Skill 两种结构不同的管线上验证，增强推广性论证；四个安全效应家族提供了攻击影响的广度。
- **机制消融设计**：RQ2 系统隔离了重复支持、因果框架和领域编码的各自贡献，结论有据可依。
- **实验安全性**：使用惰性金丝雀（临时路径、环回注册表、玩具标志），不执行真实攻击行为，研究伦理规范。
- **防御延伸**：提出 provenance-diversity gate 作为试点，虽初步但指明了可行的防御方向；讨论中明确区分“工件级投毒”与“运行时影响”，避免混淆指标。

### 八、不足与局限

- **单轮进化限制**：实验止于一个进化周期，未测量多轮进化的反馈回路效应（投毒技能引导后续轨迹、使模式看似独立验证）；作者明确承认这一点，建议以版本化谱系和反事实评估缓解。
- **系统覆盖范围有限**：用户作用域的对话记忆系统、验证器系统、参数训练耦合系统（CoEvoSkills、SkillRL、Skill-SD、MemSkill）不在实证范围内。
- **C1未被独立消融**：包含条件作为操作固定条件处理，未单独评估过滤器变化对攻击成功率的影响。
- **C3 消融设计非单变量**：类别编码与工作流位点同时变化，无法精确归因单个因素；作者明确承认这是压力测试而非精确因果估计。
- **防御验证初步**：provenance-diversity gate 的候选分组经假设给出、干净对照组小、协调 Sybil 可能模拟多样性；论文仅称其为试点。
- **良性效用检查范围窄**：仅一个模型、一个分裂，不是完整的效用-安全帕累托前沿的探索。
- **攻击者假设限制**：要求攻击者拥有与目标技能相关的候选轨迹且能访问技能工件；对完全无技能可见性的场景未做系统性评估。
- **家族覆盖非穷尽**：仅涵盖四类代表性安全效应，不声明为全面分类。
- **硬件细节缺失**：未报告GPU型号、数量、总推理成本，影响结果的可复现性和大规模部署的成本评估。
