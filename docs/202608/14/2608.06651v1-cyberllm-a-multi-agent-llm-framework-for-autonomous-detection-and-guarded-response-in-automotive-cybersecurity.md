## 摘要
软件定义汽车（SDV）在源代码、运行时日志和部署拓扑中扩展了汽车攻击面，而安全约束禁止自主代理在无监督的情况下行动。本文提出了CyberLLM，一个多智能体、LLM编排的框架，在正式的运行时安全保护下自主检测漏洞并执行修复。检测结合了确定性层（正则规则、AST分析器和拓扑图检查）与LLM精化过程，因此高召回率底线 complemented by 高精度推理。决策代理汇总发现，将其标记为以人为中心的资产分类法，并选择分级响应，通过有符号的跨会话记忆和重新规划反馈逐步提升置信度。每个动作在允许运行之前都会根据四个上下文安全属性和独立的动作对齐预言机进行验证，被拒绝的动作会触发升级和重新规划。对称的攻击流水线生成并重放漏洞利用，以便双方能在相同场景下进行演练。在一个独立的、基于真值基准的九个原始汽车ECU模块（使用C、C++和Rust）上，播种了47个分层漏洞以及干净控制，始终在线的确定性层以完美精度覆盖34%的标记漏洞，加上基于grounded的LLM精化和完整性检查，覆盖率约翻倍至约70%（F1为0.83），同时在干净控制上产生零误报。结果表明，当LLM代理被包裹在确定性、可审计的安全保护外壳中时，它们可以执行有用的自主网络防御。

## Abstract
Software-Defined Vehicles (SDVs) expand the automotive attack surface across source code, runtime logs, and deployment topologies, while safety constraints forbid autonomous agents from acting without oversight. This paper presents CyberLLM, a multi-agent, LLM-orchestrated framework that autonomously detects vulnerabilities and executes remediations under a formal, runtime safety guard. Detection combines a deterministic layer (regex rules, AST analyzers, and topology graph checks) with an LLM refinement pass, so a high-recall floor is complemented by high-precision reasoning. A decision agent aggregates findings, tags them with a human-centric asset taxonomy, and selects a tiered response, ratcheting its confidence with signed cross-session memory and re-planning feedback. Every action is validated against four contextual security properties and an independent action-alignment oracle before it is allowed to run, and refused actions trigger escalation and re-planning. A symmetric attack pipeline generates and replays exploits so both sides can be exercised on the same scenarios. On an independent, ground-truthed benchmark of nine original automotive ECU modules in C, C++, and Rust seeding 47 layered vulnerabilities plus clean controls, the always-on deterministic layer covers 34\% of the labeled vulnerabilities at perfect precision, and adding the grounded LLM refinement and completeness passes roughly doubles coverage to about 70\% (F1 $0.83$) while producing zero false positives on the clean controls. The results indicate that LLM agents can perform useful autonomous cyber-defense when wrapped in a deterministic, auditable safety envelope.

## 2. 论文提出的方法论

### 2.1 核心设计思想

CyberLLM采用**两阶段流水线**：先检测，后受保护的响应。其核心思想是"**确定性兜底 + LLM 增强 + 独立安全卫士**"——用确定性分析器提供高召回率底线，用LLM提升推理精度，再用形式化安全卫士保证一切动作安全合规。

### 2.2 检测阶段

**确定性层**（始终开启，无LLM）：
- **代码扫描**：基于YAML规则库的正则匹配，每条规则包含rule_id、severity、pattern等字段。
- **日志扫描**：手工编写的时序/统计检测器（如60秒内≥10次失败认证即暴力破解、广播风暴、高熵DNS查询、批量数据渗出等）。
- **部署拓扑扫描**：将部署YAML加载为actor/datasource图，检查8条拓扑不变量（TOP-001至TOP-008）。
- **可选AST层**：调用Bandit（Python）或Semgrep（其他语言）在沙箱子进程中运行。
- 所有确定性检测结果统一输出为Finding记录格式，便于与LLM输出合并。

**LLM精化层**：
- 每个扫描器将确定性命中作为上下文注入LLM，要求LLM精化、解释或扩展（非凭空发明）。
- 源码扫描器增加额外的"你遗漏了什么？"审查pass，针对正则无法发现的语义缺陷（数据竞争、TOCTOU、释放后使用、整数溢出）。
- LLM发现只有在落在新的不同位置时才被接受；若只是重述确定性规则则不重复计入。

### 2.3 决策与响应阶段

- **决策代理**：聚合所有扫描发现，确定响应层级（有/软/中/硬）、置信度、涉及的资产类别。
- **确定性、仅升级策略**：
  - 查询签名跨会话记忆，类似历史事故可使层级提升，绝不降低；
  - 若本轮先前尝试被拒绝或失败，至少提升一个层级；
  - 畸形回复安全失败为tier=none，置信度=0。
- **动作生成器**：确定性playbook为底线；可选LLM工具选择器从MCP风格工具注册表中添加步骤，但仅限只读/观察/验证类工具，禁止破坏性动作，且每个步骤需经同样的安全卫士校验。

### 2.4 安全卫士

在任一步骤执行前，SecurityGuard强制四个上下文安全属性：
- **任务对齐**（objective在允许集合内）；
- **动作对齐**（动作类型与objective兼容，通过可审计映射表）；
- **来源授权**（所有输入来自认证来源）；
- **数据隔离**（只写入可信目的地）。

动作对齐额外由**独立Ha预言机**把关——一个单独的LLM调用，只负责0/1对齐判定，只能收紧确定性决定（action_ok = static_map_ok ∧ Ha_ok），即使扫描器或决策代理被提示注入攻破，仍有未受污染的裁判。

### 2.5 跨切面机制

- **签名记忆**：SQLite存储，每次写入带HMAC签名、标记来源，读取时验证签名和来源后方可影响决策。
- **资产标记**：将每个高危发现映射到七类以人为中心的资产类别之一。
- **来源强制**：任何输入没有source和trust_level（auth/external/tool/memory）就不能进入流水线。

## 6. 论文的主要结论与发现

1. **确定性层提供了可靠底线**：仅静态确定性层即可覆盖34%（16/47）的标记漏洞，且精确率为1.000，零成本、完全离线、可复现。
2. **LLM在受约束时显著增强检测能力**：启用LLM精化+完整性审查后，覆盖率提升至约70%（33/47），F1从0.51提升到0.83，同时在干净控制上保持1.000精确率（零误报）。
3. **增益集中在正则无法发现的缺陷类别**：中危逻辑缺陷和DoS缺陷（竞争条件、离一错误、释放后使用、可触达panic）提升显著。
4. **安全包络有效**：由于守卫是仅升级机制、来源强制、Ha预言机独立且只能收紧判定，扫描器或决策代理被攻破也不会导致不安全动作执行，召回率提升不以安全包络为代价。
5. **核心结论**：LLM代理在确定性、可审计的安全保护外壳中可以进行有用的自主网络防御，为SDV安全领域提供了可落地的范式。

## 7. 优点（方法或实验设计的亮点）

- **分层检测设计巧妙**：确定性工具提供可验证的底线，让LLM做精化和扩展而非自由生成，有效遏制幻觉。统一Finding记录格式使各层无缝合并。
- **安全卫士设计严谨**：四个上下文安全属性 + 独立Ha预言机的双重把关，使得单一的故障点（如扫描器被攻破）无法导致不安全动作；Ha只能收紧、不能放松，保证安全单调性。
- **同级攻防设计**：对称攻击流水线与防御代理一一对应，复用同一规则库，使攻击与防御可在完全相同的场景下比较。
- **对抗记忆投毒防御**：HMAC签名和源验证的SQLite存储，防止学习循环被投毒，比蓝图级方案更具体。
- **专业领域适配好**：采用汽车领域的资产分类法（七类以人为中心的类别）、ECU场景、ISO 21434背景，结合MCP工具注册表，务实落地。
- **代码开源**：提供完整实现和Web界面，便于复现和后续研究。
