## 摘要
AI智能体正迅速变得更为强大并被广泛部署，有望带来显著的生产力提升并催生新型应用类别。然而，其不断增强的自主性也引入了严重的隐私与安全风险。现有防御措施主要以智能体为中心，依赖智能体自身来检测威胁并执行隐私与安全策略。这种方法本质上存在局限，因为它将策略执行委托给了AI智能体，而智能体的LLM驱动行为本质上具有非确定性，且容易受到诸如提示注入等攻击的操纵。因此，现有防御措施无法可靠地防止隐私与安全威胁，凸显出迫切需要一种新的方案来保障AI智能体系统的安全。网络社区长期以来一直面对类似挑战，并提供了富有洞察力的原则，我们可借鉴这些原则来设计更安全的AI智能体系统。这些原则包括集中控制与分布式执行、基于能力访问以调解对敏感资源的请求，以及通过零信任执行实现最小权限。从历史上看，这些原则为网络系统提供了强有力的确定性保证。然而，仅凭这些原则并不足以应对AI智能体，因为智能体行为的安全性与适当性往往取决于超出静态规则表达能力的语义上下文。基于这些原则，我们倡导一种系统化的AI智能体安全方法，将提供强安全保证的确定性执行机制与实现细致决策的语义、上下文感知策略相结合。随后，我们提出一个参考架构，并确定关键研究问题与未来方向，以指导安全且保护隐私的AI智能体系统的设计。

## Abstract
AI agents are rapidly becoming more capable and widely deployed, promising substantial gains in productivity and enabling new classes of applications. However, their growing autonomy also introduces significant privacy and security risks. Existing defenses are predominantly agent-centric, relying on the agent itself to detect threats and enforce privacy and security policies. This approach is fundamentally limited because it entrusts policy enforcement to AI agents whose LLM-driven behavior is inherently nondeterministic and vulnerable to manipulation through attacks such as prompt injection. As a result, current defenses cannot reliably prevent privacy and security threats, highlighting a critical need for a new solution to securing AI agent systems.   The networking community has long grappled with similar challenges and offers insightful principles we can borrow to design a more secure AI agent system. These include centralized control with distributed enforcement, capability-based access for mediating requests to sensitive resources, and least privilege through zero-trust enforcement. Historically, these principles have provided strong deterministic guarantees for networked systems. However, these principles alone are insufficient for AI agents because the safety and appropriateness of an agent's actions often depend on semantic context beyond the expressiveness of static rules.   Building on these principles, we advocate for a systematic approach to AI agent security that combines deterministic enforcement mechanisms, which provide strong security guarantees, with semantic, context-aware policies that enable nuanced decision-making. We then present a reference architecture and identify key research questions and future directions to guide the design of secure and privacy-preserving AI agent systems.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **核心问题**：AI 智能体（LLM-based agents）能够自主规划、推理并执行多步骤工作流，但其自主性引入了严重的隐私与安全风险——包括敏感数据泄露（个人数据、密码等）、提示注入（prompt injection）、记忆投毒（memory poisoning）和目标劫持（goal hijacking）等攻击。
- **现有防御的根本缺陷**：
  - 传统安全架构（如 RBAC、API 密钥授权）基于身份（identity-centric）和静态预定义规则，无法捕捉智能体行为的动态上下文（如数据敏感性、请求目的、下游接收者）。
  - 智能体级防御（如结构化查询、模型微调、隐私感知提示）将策略执行委托给智能体自身，但 LLM 推理本质上非确定且可被对抗性输入绕过，因此无法提供强安全保证。
- **核心论点**：**网络（network）是执行 AI 智能体隐私与安全控制的天然位置**。借鉴网络领域成功应对不可信端点的历史经验（集中控制、能力访问、最小权限/零信任），将安全策略强制置于智能体之外、位于网络边界。
- **整体意义**：论文倡导一种系统化方法——将**确定性强制机制**（提供强安全保证）与**语义上下文感知策略**（提供精细决策）相结合，并给出参考架构以指导未来研究。

## 2. 论文提出的方法论（核心思想与技术细节）

### 2.1 两大互补的抽象

- **确定性执行强制（Deterministic Enforcement）**：
  - 系统层原语，约束智能体可以做什么：可调用的工具、可达的目标、输出可流经的数据路径。
  - 与智能体的配合意愿、提示内容或模型权重无关。
  - 可类比为"以智能体执行图为保护单元而非数据包 5 元组的防火墙"，必须位于智能体推理路径之外的网络扼制点（choke point）。
- **上下文感知策略语义（Context-Aware Semantics）**：
  - 提供"适当性"的判定词汇，借鉴 Nissenbaum 的**语境完整性（Contextual Integrity, CI）** 理论。
  - CI 规范形式为 `(发送者角色, 接收者角色, 主体, 信息类型, 传输原则)`，如 `check_flow(sender, recipient, task, labels)` 函数在每一跳执行。
  - 本质上是**以 CI 规范为标签策略的信息流控制（IFC）**，网络作为参考监视器（reference monitor）。

> **关键论断**：两者必须结合，单独使用均不充分——确定性强制无语义退化为粗粒度连接控制；语义感知无确定性强制退化为当代 guardrail（由被保护实体自我执行的规范）。

### 2.2 三大设计原则（借鉴网络领域）

| 原则 | 网络先例 | 应用于智能体 |
|---|---|---|
| **集中控制（Centralized Control）** | SANE、Ethane（SDN 基础），声明式策略 + 集中控制器，逻辑集中服务器做访问决策 | 策略编译与分发由控制平面完成；智能体无法绕过或忽略 guardrail；借鉴"端到端论证"——当端点无法可靠完成任务时，应将功能置于网络中 |
| **能力访问（Capability-based Access）** | SIFF、TVA、Off-by-Default（通信默认拒绝，需先获取接收方能力） | 智能体的可达性默认关闭（off by default），必须获得策略授权的显式能力；能力需防伪、可由执行点验证、由可信策略权威颁发；开放问题：能力粒度与语义（保护资源是上下文隐私信息而非网络带宽时） |
| **最小权限/零信任（Least Privilege / Zero Trust）** | 网络边界处的信任强制 | 智能体不被预先信任，所有外部动作需经强制执行点评估 |

### 2.3 参考架构（核心技术细节）

架构分离**策略管理（控制平面）** 与**运行时强制执行（边车）**：

- **集中式控制平面（Centralized Control Plane）**：
  - 位于企业信任边界内，与智能体隔离，防止智能体篡改或绕过安全要求。
  - 分发内容：确定性规则（ACL、RBAC）、语义策略（如客户 PII 使用约束）、请求路由策略、数据敏感性标签、风险阈值、经批准的语义评估模型。
- **边车（Sidecars）**：部署于智能体旁，由 4 个子组件构成：
  - **Agent Policy Gateway（智能体策略网关）**：运行时执行点，拦截所有外部动作（工具调用、内存操作、API 请求、网络通信、文件访问、数据共享）。
  - **Request Classifier / Policy Router（请求分类器/策略路由器）**：根据策略定义的标准（动作类型、资源敏感性、风险级别）将请求路由至确定性引擎或语义引擎，实现风险自适应路由。
  - **Deterministic Enforcement Engine（确定性强制引擎）**：基于明确规则（ACL、RBAC、工具权限、网络策略、速率限制）快速评估，无需语义推理。
  - **Context-Aware Semantic Engine（上下文感知语义引擎）**：收集执行上下文（数据敏感性、动作风险、智能体角色与权限、用户意图、任务状态、近期交互），评估语义策略后返回 `允许 / 拒绝 / 修改 / 升级人工审批`。

**端到端流程**：控制平面定义策略 → 分发至网关 → 智能体发起外部动作 → 网关截获 → 分类器路由 → 确定引擎或语义引擎评估 → 执行决策 → 记录审计日志。

## 6. 论文的主要结论与发现

1. **现有智能体安全防御的根本失败模式**：将策略执行委托给本身可被操纵的非确定性 LLM，无法提供可靠保证——这是传统端点安全和现有 agent-centric 防御共同的结构性缺陷。
2. **网络是执行智能体控制的正确位置**：AI 智能体系统本质上是分布式通信实体系统，网络边界处的边界强制（boundary enforcement）是自然的安全基础。
3. **确定性 + 语义上下文的结合是必要且互补的**：前者提供"不能被绕过"的保证，后者提供"语义上是否适当"的判断；二者缺一不可。
4. **参考架构可行且可与现有基础设施集成**：控制平面/边车分离可复用企业现有的身份管理、访问控制与数据治理策略，并跨不同模型/框架/架构部署。

## 7. 优点

- **视角创新**：将智能体安全问题重新定义为网络问题，为智能体安全这个新兴领域引入了成熟且经过实践检验的设计原则（SDN式的集中控制、能力机制、零信任），而非在 LLM 层面打补丁。
- **论证深度**：精准识别了现有防御的结构性缺陷——"执行者与被约束者是同一实体"的矛盾，并引用了端到端论证（Saltzer et al.）来正当化将功能置于网络中而非端点。
- **原则到架构的完整映射**：从抽象原则（确定性/语义）推导出具体组件（策略网关、路由器、双引擎），架构清晰且部署路径明确（可与 API 网关、服务网格、PEP 集成）。
- **承认借鉴的边界**：明确指出网络原则本身不足以为 AI 智能体提供完整安全，因为动作适当性依赖静态规则无法表达的语义上下文——避免了简单类比陷阱。
- **审慎披露局限**：主动讨论上下文操纵风险、出站数据失控、ingress 方向更难等限制，并给出初步应对思路（如签名标签、预先协商）。

## 8. 不足与局限

- **概念验证缺失**：核心主张（确定性 + 语义结合可以提供更强保证）没有原型实现、没有端到端测试、没有与现有防御的实证对比；语义引擎的准确性、延迟、成本均未验证。
- **上下文操纵风险**：攻击者可在智能体供给语义引擎的上下文（tool outputs、历史交互）中注入恶意信息，导致语义引擎授权未授权的信息流或动作——该风险作者已承认但未提出解决方案。
- **仅覆盖出站（egress）流量**：架构无法控制数据离开企业后外部服务的计算行为；需要可信外部服务配合，实际部署受限。
- **入站（ingress）过滤更困难**：恶意发送者可绕过边车的检查通道；作者仅提出"发送方附带可验证标签"的方向性想法，未给出机制。
- **动态泛化不足**：静态规则难以应对智能体运行时创建子智能体、调用新工具、产生未见交互等动态行为；动态角色/信任级别的持续评估开销与权衡未解决。
- **风险路由的理论基础缺失**：策略路由器如何准确度量风险、如何避免攻击者定向改变路由行为，均只是提出的开放问题。
- **实际部署障碍未讨论**：加密流量下的检查能力（文中引用了 BlindBox 但未展开）、网关拦截引入的延迟、语义引擎在规模下的吞吐瓶颈等工程问题缺失。
- **语义策略的表达与维护成本**：CI 规范如何落地为可执行策略、如何处理规范冲突、组织如何更新策略以适应新场景，这些均未给出操作性建议。
