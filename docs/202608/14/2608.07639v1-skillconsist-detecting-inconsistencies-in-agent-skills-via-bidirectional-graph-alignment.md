## 摘要
Agent技能为LLM智能体提供了可复用的能力。Agent技能的不一致可能暴露未披露的危险行为或导致错误的技能选择。近期Agent技能研究越来越关注Agent技能一致性检测。现有方法针对预定义类别或声明范围评估行为或安全属性图。最近，PL-HCL使用基于LLM的模型学习元数据、指令和资源之间的一致性。然而，声明和实现行为可能混合在文本和代码中，且简洁的声明可能对应多个相互关联的实现步骤。我们提出SkillConsist以应对这两个挑战。LLM将声明和实现内容分离为声明侧和实现侧的行为记录，而静态分析补充实现记录。这些记录分别构成声明行为图和实现行为图。从任一侧的行为记录开始，双向图对齐在另一侧图中搜索候选子图，并沿行为关系扩展该子图，直至其完全表达源侧行为。图差异比较识别对齐子图之间的冲突并输出检测结果。我们基于ClawHub上500个下载量最高的公共技能和133个Skill-Inject包构建了一个包含633个技能的基准。该基准包含319个不一致技能和314个一致技能，以及442个局部不一致标注。在该基准上，SkillConsist在包级检测上实现了86.85%的精确率、89.03%的召回率以及87.93%的F1分数，相比最佳基线F1提升了20.43个百分点。在局部化方面，实现了67.60%的精确率、58.14%的召回率及62.52%的F1分数。

## Abstract
Agent Skills provide reusable capabilities to LLM agents. Agent Skill inconsistencies can expose undisclosed dangerous behavior or cause wrong Skill selection. Recent Agent Skill research has increasingly examined Agent Skill consistency detection. Existing methods evaluate behaviors or security-property graphs against predefined categories or declared scopes. More recently, PL-HCL uses an LLM-based model to learn consistency across metadata, instructions, and resources. However, declaration and implementation behavior can be mixed across text and code, and a concise declaration can correspond to multiple connected implementation steps. We present SkillConsist to address both challenges. An LLM separates declaration and implementation content into behavior records on the implementation and declaration sides, while static analysis supplements implementation records. These records form declaration and implementation behavior graphs, respectively. Starting from a behavior record on either side, bidirectional graph alignment searches the other graph for a candidate subgraph and expands it along behavior relations until it completely expresses the source-side behavior. Graph differencing identifies conflicts between aligned subgraphs and outputs the detection results. We construct a 633-Skill benchmark from ClawHub's 500 most-downloaded public Skills and 133 Skill-Inject packages. The benchmark contains 319 inconsistent and 314 consistent Skills and 442 localized inconsistency annotations. On this benchmark, SkillConsist achieves 86.85% precision, 89.03% recall, and 87.93% F1 for package-level detection, improving F1 over the best baseline by 20.43 percentage points. For localization, it achieves 67.60% precision, 58.14% recall, and 62.52% F1.

## 1. 论文的核心问题与整体含义

- **研究背景**：Agent Skill 为 LLM 智能体提供可复用的能力，但存在“声明行为”（Skill 声称提供的功能）与“实现行为”（实际执行的代码/逻辑）不一致的风险。这种不一致可能导致智能体选择错误的技能，或执行声明范围之外的危险行为（如恶意技能隐藏未声明的能力）。
- **现有方法的不足**：
  - 已有工作（如 SKILLSCOPE、BIV、PL-HCL）通常基于预定义类别或声明范围进行比对，且大多假设声明与实现文本/代码已被明确区分。
  - 实际中，声明和实现行为常混合在自然语言与代码片段中（例如一句自然语言指令可能参与实现，而一个命令示例可能属于声明）。
  - 声明和实现粒度天然不匹配：一句简洁声明可能对应多个相互连接的实现步骤，因此难以用一对一比较处理。
- **核心问题**：如何自动、准确地检测 Agent Skill 中声明与实现之间的不一致性，并定位到具体行为/位置。
- **整体含义**：这项研究提供了一种结构化检测方法，通过双向图对齐来弥合文本/代码混合以及粒度差异，提升 Agent 技能安全评估能力。

## 2. 论文提出的方法论

- **核心思想**：将声明侧和实现侧分别建模为“行为图”，通过双向图对齐建立跨侧行为对应关系，再用图差分和覆盖检查输出三类不一致：冲突（Conflict）、未实现（Unimplemented）、未声明（Undeclared）。
- **方法流程**（SkillConsist 分三阶段）：
  1. **角色分离与行为记录提取**：
     - 将包内文件按自然边界分段，利用 LLM 将声明/实现事实转换为行为记录 `K=<C, O, R, E>`（条件、对象、效果、源位置）。
     - 静态分析从源码、配置和受控执行中补充实现记录（公共入口、调用、输入输出、配置绑定、路径等）。
  2. **行为图构建**：
     - 每个记录作为记录节点；对象、公共入口、证据分别作为对应节点。
     - 构建有向图 `G_X=(V_X, A_X)`，包含六种边关系：`APK`（入口→记录）、`AKO`（记录→对象）、`AEK`（证据→记录）、`ARI`（结果→输入）、`ARC`（结果→条件）、`ACC`（条件→条件）。
     - 通过图中连通的记录子图形成“行为组”，并导出类型化转移集合 `T_X` 用于后续比较。
  3. **双向图对齐与差分**：
     - 分别在 `D→M` 和 `M→D` 两个方向执行：以源侧行为组为查询，通过锚定记录在目标图中检索候选目标记录，并沿关系边扩展子图，直到满足绑定和四项完整性检查（`Cond`, `Input`, `Result`, `Path`）。
     - 对齐条件（公式）：`Align(B_Q, H)` 要求绑定成功且所有 z∈Z 检查通过。
     - 图差分通过“类型化转移证明”得到四值结果（Supported/Contradicted/Not-Applicable/Unknown），只对 Contradicted 输出冲突。
     - 覆盖检查在无对齐候选时，基于完整性证书判定缺失侧行为：`Reach` 和 `Obs` 约束实现侧行为范围。
- **算法**（Algorithm 1）：
  1. 构建图和行为组；
  2. 对每个源行为组，目标候选集 `H`；
  3. 对每个候选计算证明 πH，若 Contradicted 记录冲突，若 Supported 记录已对应；
  4. 若未找到支持/矛盾候选且覆盖证书 Complete，则根据方向输出 Unimplemented 或 Undeclared；
  5. 最后合并去重并输出带源位置的结果。
