## 摘要
集成外部工具的大型语言模型（LLM）代理容易受到嵌入在环境状态中的间接提示注入攻击。然而，现有研究大多依赖于手动实现或复用环境、基于随机LLM的工具模拟以及预定义的注入位置，限制了在更广泛领域中进行可扩展的安全研究。为弥补这一差距，我们提出了**ToolHazard**，一种可扩展的对抗环境合成框架，可减少人工工程，并支持通过额外的种子领域和计算进行扩展。通过环境模拟器、攻击者代理和用户模拟器，ToolHazard合成可执行的有状态环境，发现可行的注入点并生成环境特定的载荷，以及构建基于状态的长时程任务。基于ToolHazard，我们构建了**ToolHazard-Bench**，用于在复杂工作流和多样化环境攻击下对代理进行压力测试。实验揭示了代理存在重大漏洞，并表明注入时机和位置会影响攻击有效性。此外，ToolHazard生成的对抗数据在ToolHazard-Bench和AgentDojo上均提高了安全性，同时保持了良性任务的实用性。

## Abstract
Large language model (LLM) agents integrated with external tools are vulnerable to indirect prompt injections embedded in environmental states. However, existing studies largely rely on manually implemented or reused environments, stochastic LLM-based tool simulation, and predefined injection locations, limiting scalable security research across broader domains. To bridge this gap, we propose **ToolHazard**, a scalable adversarial environment synthesis framework that reduces human engineering and supports expansion with additional seed domains and compute. Through an Environment Simulator, an Attacker Agent, and a User Simulator, ToolHazard synthesizes executable stateful environments, discovers viable injection points and generates environment-specific payloads, and constructs state-grounded long-horizon tasks. Based on ToolHazard, we build **ToolHazard-Bench** for stress-testing agents under complex workflows and diverse environmental attacks. Experiments reveal substantial agent vulnerabilities and show that injection timing and placement affect attack effectiveness. Moreover, ToolHazard-generated alignment data improves security on both ToolHazard-Bench and AgentDojo while preserving benign task utility.

- **现有研究的核心瓶颈**：
  1. **环境构建成本高**：现有基准（如 ASB、AgentDojo、AgentLAB、PIArena）主要依赖手工实现或复用环境，扩展到新领域代价高昂。
  2. **可复现性差**：基于 LLM 的工具模拟（如 Ruan et al., 2024）虽然能扩大覆盖范围，但其随机反馈导致评估不可复现，也难以支撑可靠训练。
  3. **注入点发现缺失**：现有自动化红队方法通常针对**预定义注入位置**优化攻击载荷，而非主动发现新环境中的可行注入点和传播路径。
- **核心意义**：论文提出 **ToolHazard**，一个可扩展的对抗环境合成框架，旨在以最低人工成本、动态合成跨领域的可执行有状态对抗环境，同时支撑**安全评估**与**对抗对齐（adversarial alignment）**，将代理安全研究拓展到更广泛的应用领域。

### 二、方法论：核心思想、关键技术细节

**整体框架**：ToolHazard 由三个核心模块组成——环境模拟器（Environment Simulator）、攻击者代理（Attacker Agent）和用户模拟器（User Simulator），并辅以验证函数生成模块。

#### 1. 环境模拟器（Environment Simulator）

采用 LLM 驱动的三级流水线，将种子任务数据集自动转化为可执行环境：

- **环境蓝图规划（Blueprint Planning）**：
  - 环境类型推断：从原始任务中推断潜在的有状态领域环境；
  - 状态与规则推断：推导状态表示、实体模式和操作约束；
  - 操作推断：推断信息查询（query）与状态修改（state change）操作。
  - 形式化表示为：`B = f_ops(f_state(f_env(D)))`，其中 `B = ⟨E, R, T⟩`。
- **可执行程序构建（Executable Program Construction）**：将蓝图翻译为面向对象（OOP）的 Python 环境程序 `P = f_code(B)`，环境实现为类，实体实例化为类属性，工具实现为可调用方法，规则由 `R` 约束。
- **自动化质量检查（Automated Quality Inspection）**：采用**双代理验证管道**——测试代理（Testing Agent）调用工具、检查代理（Checking Agent）验证执行正确性与规则一致性。环境质量分数 `score_env = (1/N) Σ Judge(a_i)`，低于阈值的环境被丢弃。

#### 2. 用户模拟器（User Simulator）

- **环境状态初始化**：`S_init = f_init(E, R, T)`，基于环境骨架生成初始状态；
- **用户任务生成**：`q = f_task(S_init, E, R, T)`，合成状态接地（state-grounded）的长时程任务（"先读后写"模式）。

#### 3. 攻击者代理（Attacker Agent）

- **环境攻击点发现（三阶段）**：
  1. **可注入属性识别**：基于规则类型分析与 LLM 语义过滤，区分自由文本字段（如评论、邮件正文）与受限字段（如 ID、时间戳）；
  2. **操作读写分析**：LLM 分析工具语义与源码，构建操作-状态依赖图；
  3. **攻击点匹配**：保留同时具备写路径与读路径的属性，得到完整的"攻击者注入→代理感知"传播链。
- **对抗注入管道（两阶段）**：
  1. **轨迹对齐攻击点过滤**：基于良性执行轨迹，按读路径激活时间排序（越早优先级越高），仅保留执行中可观察的注入位置；
  2. **计划-执行对抗注入**：规划阶段选择攻击点并生成注入计划（载荷 + 攻击策略）；执行阶段通过读操作获取原始属性内容，追加生成载荷（**追加而非覆盖**，保持良性任务信息完整）。
- **六种预定义注入策略**（Payload Wrappers）：基础组合（Basic Combined）、重要模板（Important-Template）、多轮（Multi-turn）、决策劫持（Decision Hijacking）、推理标准（Reasoning-Criteria）、工具选择（Tool-Selection）。

#### 4. 验证函数生成

- 给定任务 q，LLM 将其分解为可验证条件集合 `{c_k} = g_cond(q)`，再为每个条件生成验证函数 `f_ck = g_verifier(c_k, q)`，最终得分 `Score = (1/K) Σ ⊮[f_ck(S_final)=1]`。
- 所有检查仅依赖最终状态 `S_final`，与执行轨迹无关，支持多条有效解路径。

#### 5. 数据生态

- **ToolHazard-Bench**：28 个测试环境（与训练环境不相交），87 个长时程任务，512 个工具，平均执行步数 15.56；
- **ToolHazard-Align**：60 个训练环境、300 个环境-任务实例、1800 个攻击候选（过滤后 1040 个）；其中 329 个用于 RL，711 个用于 SFT。
- **奖励定义**：`R(τ) = R_task(τ) − R_injected(τ)`，同时衡量良性任务完成度与是否被劫持。

### 六、主要结论与发现

1. **最先进的 LLM 代理仍高度脆弱**：几乎所有评估模型在对抗环境中都表现出高 ASR。四种攻击策略对 GPT-5 达到 40%+ ASR，三种对 Gemini-3.1-Pro 超过 30%。DeepSeek-V3.2 良性任务成功率最高但同时最易受攻击；Qwen3-4B 因指令遵循能力较弱反而受影响较小——**更强的模型可能更容易受到环境提示注入的影响**。
2. **新兴攻击策略构成更大威胁**：现代模型对之前研究过的攻击（如 basic combined）有部分鲁棒性，但新引入的策略（decision hijacking、tool selection、reasoning criteria）在多个模型上持续取得高 ASR，暴露了当前安全对齐的关键弱点。
3. **能力提升只带来边际安全改善**：新一代模型（GPT-5 vs GPT-4.1、Gemini-3.1-Pro vs Gemini-2.5-Pro）BR 更高、ASR 更低，但远不足以可靠防御提示注入。
4. **注入时机与位置显著影响攻击效果**：越早被代理遇到的注入指令攻击成功率越高；注入内容位于工具响应**末尾字段**时攻击更有效（位置偏差效应）。
5. **输出格式影响安全性**：自由文本格式的攻击成功率显著高于 JSON/YAML 结构化格式——结构化格式通过显式语法提供了部分"语义隔离"。
6. **攻击不仅引发不安全行为，还系统性损害良性任务执行能力**（BR 普遍下降）。
7. **ToolHazard-Align 能有效提升安全性**：在 ToolHazard-Bench 和 AgentDojo 上均显著降低 ASR 并提升 BR，且**跨环境、跨攻击策略泛化**；SFT 保留效用，未观察到

SFT 保留效用，未观察到安全对齐带来的良性能力显著退化，表明通过对抗性训练提升代理安全的路径是可行的。
8. **跨攻击策略泛化能力**：留出策略实验表明，在训练阶段仅使用部分攻击策略时，模型对未见攻击策略仍具有非平凡的泛化能力，但 ASR 仍处于较高水平，说明完全依赖已知攻击模板的对齐方法不足以应对未知威胁；这一结果与已有对抗鲁棒性研究一致。
9. **合成环境的有效性**：ToolHazard 通过 LLM 流水线以可忽略的成本（每环境约 $0.59）合成高质量、可执行、可验证的环境，人工验证显示环境与任务有较高的正确性和可执行性，初步说明该框架能有效弥合“环境构建成本”与“可复现评估”之间的鸿沟。

### 七、局限性

尽管 ToolHazard 在框架设计和实验规模上都具有较强的贡献，但仍存在若干不可忽视的局限：

- **环境真实性与复杂度的偏差**：合成环境尽管是有状态的，但相较于真实世界的复杂系统（如 ERP、云控制台、银行后端），其状态数量和交互逻辑的复杂性仍有限。工具数量虽达 512 个，但每个工具的语义相对简单，攻击路径的丰富程度可能与真实系统存在差距。
- **威胁模型的覆盖狭窄**：论文关注的是环境侧（间接）提示注入，即注入点位于工具返回的环境内容中。对于直接注入（用户自行诱导）、跨会话记忆注入、多代理通信中的后门以及供应链注入，本框架未做系统处理。这使得安全性结论不能直接推广到所有代理威胁模型。
- **生成流程的级联错误风险**：框架中环境、任务、验证函数、攻击载荷均由 LLM 合成，虽然有人工抽样验证，但无法完全排除生成错误、语义偏差或验证函数与任务不匹配的风险。验证函数本身也可能是偏置的，例如宽松的检查条件可能高估良性任务完成率。
- **攻击策略仍偏模板化**：六种攻击策略本质上是预定义的指令包装模板（wrapper），并非针对代理推理模式自适应优化的攻击。对于推理能力更强、系统提示词设计更完善的模型，真实攻击者可能开发出更隐蔽、多模态或时序更复杂的注入手法。
- **对模型规模的覆盖有限**：对齐实验只使用 4B/8B 的 Qwen3 系列模型，未扩展到 70B 级或更大模型，因此难以判断 ToolHazard-Align 在大模型上的有效性与 RL 稳定性。
- **指标设计仍有提升空间**：BR 和 ASR 是最终状态层面的二值判定，对于部分“部分完成”“仅在早期阶段被劫持后回归正常”等部分成功情形缺乏细粒度测量；同时报告平均值而未附置信区间或分环境方差，影响统计可靠性推断。

### 八、未来研究方向

作者在论文中没有独立设置“Future Work”章节，但从整体研究图谱和实验遗留问题来看，可以合理推断以下几条有前景的延伸方向：

1. **更复杂的多步可执行环境**：引入更多真实系统接口（浏览器环境、API 网关、数据库引擎）以及带权重的状态转移，使攻击评估更贴近生产环境。
2. **自适应攻击（adaptive attack）生成**：利用攻击代理在环境中反复探索，根据目标模型的防御表现动态演化载荷，构建更强大的红队评估。
3. **面向大规模模型的对齐扩展**：将 ToolHazard-Align 扩展到更大参数规模（如 70B 或 405B），并验证 RL 稳定性与安全–效用帕累托前沿。
4. **多模态与长上下文代理安全**：在图像、语音、结构化数据等非纯文本载体中执行注入攻击，探索多模态输入的提示注入风险。
5. **防御机制的一体化整合**：将基于训练的对齐与运行时检测（如注入分类器、特权分离、工具调用审计）结合起来，构建纵深防御体系。

### 九、该工作的贡献与领域启示

- **方法论贡献**：ToolHazard 第一次提出了一套**端到端、可扩展的对抗环境合成流水线**，将环境构建从昂贵的人工编写中解放出来，为代理安全研究提供了可复现的基础设施。这个贡献的意义已超出论文自身的实验结果，因为它使后续研究者可以在几十美元的成本内自定义安全评估环境。
- **评估贡献**：ToolHazard-Bench 提供了目前任务平均执行步骤最长（15.56 步）且有状态、有可验证检查的代理安全基准，显著提升了安全评估任务的复杂度和真实性。
- **对抗对齐贡献**：通过 SFT + RL 的对抗对齐，展示了用合成攻击数据提升安全性的可行性，并为跨基准泛化提供了首个实证证据（ToolHazard-Align → AgentDojo）。
- **实证发现贡献**：论文揭示的“更强模型可能更容易受环境注入影响”“结构化输出降低攻击成功率”“注入时序效应”等结论，对代理安全体系设计具有直接指导意义。

### 十、个人综合评估

**优点总结**：

- 问题重要且时机恰当：在大模型代理开始大规模落地的阶段，系统性地研究间接提示注入安全是极其必要的。
- 框架设计完整、封闭：从环境生成到攻击注入再到验证与对齐，形成了“合成–评估–训练”闭环，这在同类工作中很少见。
- 成本透明、可复现：论文给出了具体的合成成本（$0.59/环境，$0.03/任务，$0.05/攻击实例）和明确的训练配置，降低了复现门槛。
- 实验维度丰富：主实验 + 机制分析 + 对齐 + 泛化 + 人工验证，在单篇论文中内容密度很高。

**缺点与风险**：

- 环境与攻击的“合成性”天然限制了结论生态效度，需在真实环境（如浏览器任务、真实 API）中进一步交叉验证。
- 攻击策略的模板化使得评估结果可能低估真实攻击者绕过对齐后产生的 ASR，因此论文中的 ASR 应解读为“基准威胁水平”而非“真实世界攻击成功率上限”。
- 论文对现有防御工作（如提示注入检测器、权限隔离、人类审核回路）的对比不足，可能让读者高估基于训练的对齐是唯一或最优解。

总体而言，**ToolHazard 是一篇方法创新突出、工程实现扎实、实证结论丰富的高质量代理安全研究**。它为该领域提供了可扩展的基础设施和清晰的对齐路线图，虽然存在合成环境真实性与攻击自适应性的固有局限，但作为代理安全评估与训练的统一框架，其思路很可能成为后续研究的重要参照。推荐对该领域有研究需求（尤其是从事 LLM Agent 评估、红队、对齐训练）的读者精读其方法与实验部分。
