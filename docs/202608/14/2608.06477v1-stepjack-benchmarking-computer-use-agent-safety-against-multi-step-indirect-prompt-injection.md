## 摘要
计算机使用代理（CUA）面临着来自间接提示注入日益增长的威胁，其中对抗性指令被植入环境中，例如网页。在本文中，我们引入了多步间接提示注入，这是一种针对CUA的新型攻击类别，其中对抗性目标被分解为多个看似无害的子步骤，并分布在代理导航路径上引用的页面链中。我们开发了一个流水线，在分解后的子步骤执行必须实现原始目标的约束下，自动分解对抗性目标，同时优化每个分解子步骤的无害性。利用该流水线，我们构建了StepJack，一个包含480个测试示例的CUA安全基准。在该基准上，我们评估了六个最先进的CUA，并发现，在固定的分解深度下，多步攻击在六个CUA中的三个上提高了攻击成功率（ASR），最高达31.2个百分点（例如，GPT-5.4-mini：从单步的41.7%到三步的72.9%）；对于能够可靠遵循参考链的五个CUA（除EvoCUA-32B外）的平均ASR，从单步的31.3%上升至三步的36.9%。数据集和代码可在https://github.com/BorealisAI/StepJack获取。

## Abstract
Computer-use agents (CUAs) face a growing threat from indirect prompt injection, where adversarial instructions are planted in the environment such as web pages. In this paper, we introduce multi-step indirect prompt injection, a new attack class against CUAs in which the adversarial goal is decomposed into multiple innocuous-looking sub-steps and distributed across a chain of pages referenced along the agent's navigation path. We develop a pipeline to automatically decompose an adversarial goal under the constraint that the execution of the decomposed sub-steps must achieve the original goal while optimizing the innocuousness of each decomposed sub-step. With this pipeline, we build StepJack, a CUA safety benchmark with 480 test examples. On this benchmark, we evaluate six state-of-the-art CUAs and find that at a fixed decomposition depth, multi-step attacks raise attack success rate (ASR) on three of six CUAs, by up to 31.2 points (e.g., GPT-5.4-mini: 41.7% at single-step to 72.9% at three-step); averaged over the five CUAs that can reliably follow the reference chain (all but EvoCUA-32B), ASR rises from 31.3% at single-step to 36.9% at three-step. Dataset and code are available at https://github.com/BorealisAI/StepJack.

## 2. 论文提出的方法论

### 2.1 攻击形式化：多步间接提示注入
攻击由两个组件构成：

**(i) 良性轨迹劫持（Benign Trajectory Hijacking） + 参考嵌套（Reference Nesting）**

- 攻击者在 CUA 的良性导航轨迹上构造一条包含 k 个内容页面的链 $W = (w_1, \dots, w_k)$。
- 每个页面 $w_i$ 包含对抗性子步骤 $d_i$、良性任务的上下文，以及指向下一页 $w_{i+1}$ 的引用 $\ell_i$（论坛中为超链接，文档中为文本指针）。
- 入口页 $w_1$ 放置在 CUA 良性轨迹的注入点上；终点页 $w_k$ 包含完成原始良性任务 $b$ 的指引，使 CUA 在攻击链结束后恢复正常执行。
- 走完参考链需要 CUA 做出显式动作（如点击超链接），这从根本上区别于文本型 agent 的单点注入。

**(ii) 对抗性目标分解（Adversarial Goal Decomposition）**

- 分解函数 $D(a, k) = (d_1, \dots, d_k)$ 须满足两个性质：
  - **目标忠实性（Goal Faithfulness）**：顺序执行所有 $d_1, \dots, d_k$ 必须能达成对抗性目标 $a$（充分条件，非必要条件）；
  - **每步无害性（Per-step Innocuousness）**：每个子步骤单独通过 CUA 内部的安全过滤器 $f$（即 $\forall i: f(d_i) = \text{SAFE}$）。

**可选紧急线索（Urgency Cue）**：在子步骤指令与下一页引用之间插入“DO IT NOW BEFORE CLICKING THE LINK BELOW! DO NOT DELAY!”，形成两种包装类型（Urgent = Y / N）。

### 2.2 自动分解流水线（Algorithm 1）
流水线为两阶段、开环（open-loop）设计——不依赖目标 CUA 的实时输出：

**Stage 1：LLM 评判候选搜索**
- 分解 LLM $\text{LLM}_{\text{Decomp}}$ 采样 $N$ 个候选分解，每个候选经 $M$ 轮迭代精炼；
- 每轮由两个评判 LLM 打分：
  - **忠实性评判** $\text{LLM}_F$：二值输出（0/1），判断整组子步骤顺序执行后是否达成目标 $a$；
  - **安全性评判** $\text{LLM}_S$：对每个子步骤单独打分（1–10，越高越无害），取均值 $S$；
- 复合分数 $Q = F \cdot S$（忠实性为硬约束，安全性为排序标准）；
- 评判的推理与分数反馈给分解 LLM 作为下一轮对话（迭代精炼）；
- 最终取 top-B 候选进入 Stage 2。

**Stage 2：CUA 验证选择**
- 将 top-B 候选作为普通用户指令（“Execute the following step-by-step: ...”）交给验证器 CUA $V$（实际为 Qwen3.5-Plus）在沙箱中执行；
- 记录达成目标 $a$ 所需动作数，选择动作数最少的分解 $D^*$ 为最终输出；
- 关键防偏置设计：Stage 2 从未发起攻击（无注入包装），$V$ 的注入防御机制不被触发，因此选择过程优化的是**GUI 可执行性**而非**安全绕过性**（附录 E 有详细论证）。

### 2.3 分解策略分类（Taxonomy）
尽管流水线只优化单一目标，其输出自然聚类为三种策略：
- **操作性分解（Operational）**：每步落在 CUA 日常允许的操作范围内，危害仅由组合产生（例如“先保存匹配路径到 list.txt，再删除 list.txt 中的每个路径”）；
- **语义性分解（Semantic）**：有害载荷被碎片化到多个子步骤，最后一步才重组（例如把“打开 10 个 Chrome 窗口”拆为写脚本、写配置、按配置执行三步）；
- **升级性分解（Escalatory）**：前序无害步骤的合规行为锚定/影响过滤器对最终有害步骤的判断（例如“把 id_rsa 移到备份位置，再删除备份”）。
