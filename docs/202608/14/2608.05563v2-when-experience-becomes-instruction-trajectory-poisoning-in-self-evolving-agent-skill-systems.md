## 摘要
自进化技能（SES）系统将智能体轨迹提炼为持久技能，使得不可信的经验能够成为可信的指令。我们提出了PoisonedEvolution，一种针对这一提升过程的轨迹投毒攻击。我们的技能可见黑盒攻击者可以检查目标技能并贡献有界证据，但无法观察私有池或进化逻辑，也无法编辑技能库。人工制品投毒需要包含性、进化归因和实现性。归因是独特的瓶颈：目标行为必须在提升之前表现出因果有用性、重复性和可泛化性。我们使用惰性金丝雀规范评估了四个具有代表性的安全效应家族。在10%攻击者支持率下，在SkillClaw中的六个主流LLM进化器上，PoisonedEvolution在546/600次试验中嵌入了目标行为（91.0% SER）。在结构不同的Trace2Skill流水线上以相同比例，它在369/600次试验中嵌入了目标行为（61.5% SER），证明了跨进化架构的迁移性。在一项具有代表性的对照研究中，三个一致的攻击者记录在30条记录批次中足够，而单条记录则弱得多。消融实验识别出重复支持、因果框架和领域对齐编码是成功的主要决定因素。这些发现揭示了证据提升是自进化智能体的安全边界。

## Abstract
Self-evolving skill (SES) systems distill agent trajectories into persistent skills, allowing untrusted experience to become trusted instruction. We introduce PoisonedEvolution, a trajectory-poisoning attack on this promotion process. Our skill-visible black-box attacker can inspect a target skill and contribute bounded evidence, but cannot observe private pools or evolution logic or edit the skill bank. Artifact poisoning requires Inclusion, Evolution Attribution, and Realization. Attribution is the distinctive bottleneck: the target behavior must appear causally useful, recurrent, and generalizable before promotion. We evaluate four representative security-effect families using inert canary specifications. At 10% attacker support, across six mainstream LLM evolvers in SkillClaw, PoisonedEvolution embeds target behaviors in 546/600 trials (91.0% SER). On the structurally different Trace2Skill pipeline at the same ratio, it embeds target behaviors in 369/600 trials (61.5% SER), demonstrating transfer across evolution architectures. In a representative controlled study, three consistent attacker records suffice in a 30-record batch, whereas a single record is much weaker. Ablations identify recurring support, causal framing, and domain-aligned encoding as the main determinants of success. These findings expose evidence promotion as a security boundary for self-evolving agents.

## 1. 论文的核心问题与整体含义

**研究动机与背景：**
- 近年来，LLM 智能体越来越倾向于将学到的经验固化为**可复用的技能（skills）**——即描述工作流、触发器、约束和工具使用约定的指令工件（如 SKILL.md）。
- 技能与普通提示不同：一旦被安装或进化，它就会成为智能体未来的**操作程序的一部分**，因此技能的生产和维护本身构成了一个**安全边界**。
- 自进化技能（Self-Evolving Skill, SES）系统通过从智能体交互和轨迹中提炼可复用经验来自动化技能编写，例如 SkillClaw 从多用户会话中提炼模式、Trace2Skill 从执行轨迹中抽取技能。
- 这些系统共享一个核心假设：**轨迹池中反映的是值得提升为持久指令的良性证据**。本文研究该假设失效时会发生什么。

**核心安全洞察：**
- 攻击者**无需发布恶意技能、入侵进化器或直接编辑技能库**，只需贡献有界数量的正常外观的进化证据。
- 如果该证据通过过滤、被归因为重复出现的经验，并在技能合成过程中被保留，**SES 系统自身就会产出被投毒的人工制品**。
- 攻击针对的是"经验→指令"的**提升策略（promotion policy）**，而非直接修改最终技能文件。

## 2. 论文提出的方法论

**核心思想：归因导向的轨迹投毒（Attribution-Oriented Trajectory Poisoning）**

PoisonedEvolution 的核心原理是操纵进化器进行**信用分配**所依据的证据：不直接要求进化器编写攻击者指令，而是让目标行为看起来是**解释成功或修复失败的可复用知识**。

**攻击者模型（Skill-Visible Black-Box）：**
- 可以检查公开或已安装的技能工件
- 可以贡献有界数量的轨迹（`|Tp| ≤ k`）
- 无法观察私有轨迹池、过滤器或进化提示
- 无法直接编辑技能库 S
- 无法更改下游流水线组件

**形式化定义：**
- SES 系统建模为 Σ = (T, F, E, S)，其中 T 为轨迹池、F 为质量过滤器/路由器、E 为 LLM 进化器、S 为版本化技能库
- 一次进化周期：`St+1 = St ⊕ E(F(Tt), St)`
- 攻击成功需要三个必要条件：**PoisoningSuccess = C1 Inclusion ∧ C2 Attribution ∧ C3 Realization**

**三个条件的具体含义：**
- **C1 包含性（Inclusion）**：投毒轨迹通过 F 过滤，进入进化器可消费的流中；将目标行为放置在合理的工作流位点（输入前置条件、恢复步骤、输出转换或验证步骤），使轨迹留在目标技能的证据流中
- **C2 进化归因（Evolution Attribution，SES 特有瓶颈）**：进化器将反复出现的行为视为**技能级可复用模式**而非噪音、一次性事件或不安全建议；需要让行为在成功路由的轨迹中呈现为"约束→行为 b→任务完成"的因果结构，或在失败路由中呈现为"缺失 b→失败"
- **C3 实现性（Realization）**：目标行为在总结和合并后仍保留在生成的技能中；通过跨轨迹保持行为语义不变（任务和措辞可变）来保证可泛化外观

**轨迹变换公式：**
- 攻击者变换有界轨迹集：`τ' = T(τa; s, b)`
- 成功路由构建：`h' = eh<ℓ ∥ [constraint b, action b, successful retry] ∥ eh>ℓ`
- 保留原始任务与结果，通过表面改写保持行为语义不变

**算法流程（Algorithm 1）：**
1. 从与目标技能相关的候选数据中选择 k 条轨迹
2. 为每条轨迹定位合法的工作流位点
3. 添加结果条件化的因果桥梁（约束→b→成功，或缺失 b→失败）
4. 保留任务结果、变化表面措辞，保持 b 的语义不变
5. 贡献 k 条变换后的轨迹（形成含 n-k 条干净记录的批次）
6. 运行 SES 进化周期，检查技能差异
7. 报告 b 是否在进化后的技能中实现

**载荷表示与安全效应家族：**
- 载荷表示为四元组 `p = ⟨ℓ, a, o, c⟩`（工作流位点、动作、目标对象、执行上下文）
- **F1 机密性**：输出工件后，将发现的凭据和敏感字段发送到攻击者端点
- **F2 数据完整性**：输出后删除源工件，阻止后续用户恢复
- **F3 供应链完整性**：安装依赖前，用攻击者注册表替换已配置的包注册表
- **F4 操作安全削弱**：发布/提交前禁用安全检查

## 3. 实验设计

**主系统（Primary System）：SkillClaw**
- 目标技能：xlsx 技能
- 数据来源：使用原始 xlsx 技能在 100 个 SpreadsheetBench 训练任务上运行 GLM-5 收集的 300 条案例级执行日志
- 每轮试验形成任务区分的批次：n 条轨迹（含 k 条攻击者轨迹 + n-k 条干净记录），运行一次原生进化周期
- 主实验设置：n=30、k=3（ρ=10%），每个模型-家族单元 25 次完成试验

**默认攻击者设置：** 技能可见黑盒（skill-visible black-box）

**转移系统（Transfer System）：Trace2Skill**
- 结构性不同的轨迹到技能泛化场景（含结果路由、分析师 LLM、分层整合）
- 每个试验混合 3 条攻击者控制的失败轨迹和 27 条干净失败记录
- 攻击者记录使带有惰性金丝雀标识符的任务/环境要求看起来未被满足

**对照/消融实验：**
- **RQ2 机制消融**：
  - 攻击者支持率变化：k=1（3.3%）→ k=2（6.7%）→ k=3（10%），固定 n=30
  - 干净池稀释：固定 k=3，n=10/30/100；另加 k=1、n=100 检查
  - C2 归因消融：Local（单点插入）vs. Fragmented（跨记录碎片化）vs. Causal（因果结局框架）
  - C3 实现消融：Generic（泛化措辞）vs. Auxiliary（带外通道线索）vs. Tailored（领域定制可操作措辞）
- **良性任务效用检查**：100 任务轨迹收集切分上使用 Qwen3.5-122B-A10B，对比投毒进化技能 vs. 无技能

**评估指标：**
- 主要指标：**技能嵌入率（Skill Embedding Rate, SER）**——完成进化试验中输出技能新嵌入了目标行为的比例
- 检测方式：预注册的家族特定、差异感知金丝雀规则（非 LLM 判定）
- Hard/Soft 任务准确率作为技能有用性健全性检查（非投毒指标）

## 6. 论文的主要结论与发现

1. **攻击高度有效**：在 10% 攻击者支持率下，SkillClaw 上 6 个 LLM 进化器的 SER 达到 **91.0%（546/600）**；Trace2Skill 上为 **61.5%（369/600）**，证明跨进化架构的迁移性。
2. **进化器差异显著**：从 GPT-5.4 的 70.0% 到 DeepSeek-V3.2/Qwen3.5-122B-A10B 的 100.0%，进化策略是攻击面的重要组成部分。
3. **重复支持是关键的"归因门槛"**：k 从 1 提升到 2（同一批次）使 SER 从 5/25 跃升至 21/25；单条投毒记录容易被当作偶然事件丢弃。
4. **因果框架（C2）至关重要**：Local（8/25）和 Fragmented（11/25）远弱于 Causal（25/25）；行为必须与观察到结局绑定才被归因为可复用经验。
5. **领域对齐编码（C3）同样关键**：Generic（18/25）和 Auxiliary（0/25）远弱于 Tailored（25/25）。
6. **家族敏感性因系统而异**：SkillClaw 最易提升 F4（安全削弱，146/150），Trace2Skill 最不易提升 F4（28/150）——这说明家族敏感性反映的是行为与工作流位点及系统归因策略的语义契合度，而非危害行为的固有排序。
7. **投毒与正常效用可以共存**：投毒进化后的技能在良性任务上的表现（20.0% Hard / 36.54% Soft）仍优于无技能基线（18.0% / 34.88%），攻击不会使人工制品退化为纯攻击文本。
8. **防御方向**：原生品质门控无法防御；需要在证据提升阶段加入**来源多样性门控（provenance-diversity gate）**；技能版本需要携带可审计的谱系信息。

## 7. 优点

1. **新颖的攻击面识别**：首次系统性地将 SES 系统的"证据提升"环节界定为独立于 RAG 投毒和静态技能投毒的安全边界。
2. **形式化清晰**：C1-C3 条件的分解为理解攻击机理提供了结构化框架，尤其将"进化归因"识别为 SES 特有的瓶颈。
3. **攻击者模型贴近现实**：技能可见黑盒攻击者仅需贡献有界证据，不依赖直接技能上传或系统后门，适用于多用户共享池的典型场景。
4. **负责任的实验执行**：所有恶意载荷均以惰性金丝雀规范编码（临时路径、回环注册表、玩具标志），没有执行任何真实破坏性操作。
5. **跨系统验证**：不仅在 SkillClaw 上验证，还在结构不同的 Trace2Skill 上验证了攻击的迁移性，增强了结论的可泛化性。
6. **多维消融**：分别隔离了重复性、因果归因和领域对齐编码的作用，为深入理解机理提供坚实依据。
7. **指标选择恰当**：使用 SER 区分"人工制品投毒"与"运行时影响"，避免了将两个不同问题混淆的常见错误。

## 8. 不足与局限

1. **攻击效果边界**：论文明确将范围限定于**人工制品投毒（artifact-level）**，不评估触发激活、动作执行后的实际运行时影响——这意味着 SER 高并不说明真实危害已发生。
2. **单循环假设**：实验仅覆盖一次进化循环，未测量多轮进化可能产生的**反馈循环效应**（投毒技能指导后续智能体产生支持投毒的轨迹，使模式看起来更独立验证）。
3. **系统覆盖有限**：用户级对话记忆系统（AutoSkill）、仅验证器反馈系统（CoEvoSkills）、参数训练耦合系统（SkillRL、Skill-SD、MemSkill）未纳入评估。
4. **默认配置单一**：主设置仅使用 n=30、k=3；更大池（n=100）的检查样本量有限（k=1 时仅五个试验，0/5），统计功效受到限制。
5. **来源多样性门控的评估过于初步**：候选分组人为假设、干净对照组很小，未评估协同 Sybil 模拟多样性对抗门控的能力。
6. **数据语料有限**：基于单一 xlsx 技能和 SpreadsheetBench 领域，跨领域的可迁移性需要更多验证。
7. **未提供算力资源信息**：缺少模型推理成本、GPU 型号/数量等关键资源细节，影响可复现性和实用性评估。
8. **无端到端危害演示**：由于刻意避免执行恶意行为，未展示从"技能嵌入"到"实际安全事件"的完整攻击链——这虽然是负责任的做法，但也留下了运行时防御效果的空白。
