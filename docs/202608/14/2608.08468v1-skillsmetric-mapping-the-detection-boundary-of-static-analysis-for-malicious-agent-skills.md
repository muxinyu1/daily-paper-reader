## 摘要
智能体技能——增强基于大语言模型的智能体的指令和脚本的结构化包——正在迅速激增，但其安全属性仍未得到充分探索。我们提出了SkillsMetric，一个五阶段静态分析框架，它沿着模式密度、统计异常、数据流污点、导入异常和能力不匹配等维度对技能包进行评分。我们构建了一个包含2,266个技能的对抗性评估数据集，涵盖代码级、系统级和语义级威胁的16种攻击类型，并在完整的SkillMD-138K语料库上进行了评估。我们的框架实现了0.93的AUC和5折交叉验证的F1为73.4%±0.5%，对数据泄露（93%）和隐写有效载荷（93%）有较强的检测能力。关键在于，我们发现了根本性的盲点：使用常见shell命令的“主机破坏”攻击可绕过所有五个阶段（检测率为0%），而通过自然语言操纵的“提示注入”仅达到42%的检测率。这些发现表明，仅靠静态分析不足以保障技能安全，从而促使采用将快速静态预筛选与语义审查相结合的纵深防御架构。

## Abstract
Agent Skills---structured packages of instructions and scripts that augment LLM-based agents---are rapidly proliferating, yet their security properties remain under-explored. We present \textsc{SkillsMetric}, a five-stage static analysis framework that scores skill packages along pattern density, statistical anomaly, dataflow taint, import anomaly, and capability mismatch dimensions. We construct an adversarial evaluation dataset of 2{,}266 skills spanning 16~attack types across code-level, system-level, and semantic-level threats, and evaluate on the full SkillMD-138K corpus. Our framework achieves an AUC of 0.93 and 5-fold cross-validated F1 of 73.4\%$\pm$0.5\%, with strong detection of data exfiltration (93\%) and steganographic payloads (93\%). Crucially, we identify fundamental blind spots: \emph{host destruction} attacks using common shell commands evade all five stages (0\% detection), and \emph{prompt injection} via natural-language manipulation achieves only 42\% detection. These findings establish that static analysis alone is insufficient for skill security, motivating defense-in-depth architectures that combine fast static pre-screening with semantic review.

## 1. 核心问题与整体含义

- **研究背景**：基于大语言模型（LLM）的智能体广泛依赖“Agent Skills”（结构化技能包，包含 `SKILL.md` 指令文件和可选伴生脚本）在推理时获取过程性知识。此类技能已在 Claude Code、Gemini CLI、OpenClaw、Codex 等主要平台普及，社区贡献技能已超过 138,000 个。
- **核心安全威胁**：恶意技能包可伪装成合法功能，诱导智能体窃取凭据、安装持久后门、破坏本地文件，或通过提示注入操纵智能体行为。由于技能运行器通常将 `SKILL.md` 内容以用户级消息注入，第三方指令获得与用户直接命令相同的权限，形成“信任提升”（trust elevation）问题。
- **研究缺口**：现有研究缺乏对静态分析方法在技能安全检测中“能检测什么、不能检测什么”的系统性评估。论文旨在填补这一空白，明确静态分析的检测边界。

## 2. 方法论

- **核心思想**：提出一个五阶段静态分析框架 **SkillsMetric**，对技能包（`SKILL.md` + 伴生脚本）评分，输出 0～100 的复合风险分数。整体思路是“多层信号加权组合 + 交互奖励”，而非单一模式匹配。

- **五个分析阶段**：
  - **Stage 1 模式密度（Pattern Density）**：扫描危险关键词与代码构造（如 `exec`、`curl`、凭据路径、YAML 反序列化等），使用 50+ 条加权正则表达式覆盖 Python、Bash、JavaScript、Ruby，按内容长度归一化。
  - **Stage 2 统计异常（Statistical Anomaly）**：计算 Shannon 熵、压缩比、卡方均匀性、序列相关、整数数组分数，与良性语料基线比较（z-score），检测编码/加密/隐写载荷。
  - **Stage 3 数据流污点分析（Dataflow Taint）**：识别“源-变换-汇”（source-transform-sink）三阶段污点链，例如读取凭据→base64 编码→HTTP 发送；完整链得分最高。
  - **Stage 4 导入异常（Import Anomaly）**：标记安全相关包的不寻常组合（如 `urllib` + `base64` + `os`），与良性依赖基线对比。
  - **Stage 5 能力不匹配（Capability Mismatch）**：比较 `SKILL.md` 声明的能力与实际代码行为，检测声称良性但实际有网络/文件系统访问的技能。

- **分数组合公式**：
  \[
  S = \sum_{i=1}^{5} w_i \cdot \hat{s}_i + \text{bonus}(s)
  \]
  其中权重 \(w = (0.15, 0.20, 0.30, 0.15, 0.10)\)，\(\hat{s}_i\) 为归一化阶段分数。
  - 权重为手动设定，而非学习得到；S3（数据流污点）权重最高，因为完整污点链在良性代码中罕见、判别力最强；S5（能力不匹配）权重最低，因为良性语料中元数据声明不一致。
  - **交互奖励**：当 ≥2 个独立阶段同时触发时加 5 分，≥3 个时加 10 分；S2 不参与奖励，因其与 S1 特征不独立。
  - 使用加权和而非乘法聚合，因为许多攻击只在一两个阶段留下信号（如主机破坏在所有阶段均为零），乘法聚合会因单零而失效。

- **风险等级与阈值**：分数映射到五级风险：SAFE（<10）、LOW（10–24）、MEDIUM（25–44）、HIGH（45–69）、CRITICAL（≥70）。检测阈值 \(\tau=25\) 依据良性技能语料分布设定（95 分位数为 16.77），人口级误报率约 1.75%；\(\tau=45\) 作为自动阻止阈值。

## 6. 主要结论与发现

- **整体性能**：SkillsMetric 在混合数据集上 AUC 达 0.93，5 折交叉验证 F1 为 73.4%±0.5%（精确率 89.4%±1.7%，召回率 62.2%±0.2%）。
- **强检测能力**：代码级攻击中的网络相关威胁检测良好——数据外泄（93%）、隐写（93%）、RSA 模块加密（89%）等。
- **根本盲点**：
  - **主机破坏（Host destruction）检测率为 0%**：使用常见 shell 命令（如 `shutil.rmtree`、`os.chmod`）的操作在语法层面与合法清理脚本无法区分，所有五个阶段均无信号。
  - **提示注入（Prompt injection）检测率仅 42%**：纯自然语言操纵不携带代码级特征，被检出的样本通常内嵌了代码块，触发了模式密度评分。
- **生态现状**：138K 真实技能评分分布右偏（中位数 2.58，95 分位 16.77），在 τ=25 下 1.75% 被标记（2,414/138,133）；82.4% 为 SAFE。手动审查显示高分技能多为合法的安全工具（渗透测试、杀毒），因此高分仅代表安全相关性而非恶意性。
- **防御架构启示**：静态分析单独不足以保障技能安全，需结合 LLM 语义审查（处理静态无法判断的意图）和运行时沙箱，形成纵深防御。静态预筛可将昂贵的 LLM 推理集中在约 2% 的高风险技能上，成本比纯 LLM 审查降低约 50 倍。
- **LLM 对比（初步）**：Claude 的安全感知率（69.3%）显著高于 Gemini（29.6%）；金丝雀泄漏率 Claude 为 0.7%（1/150），Gemini 为 5.1%（12/236）。静态检测与 LLM 感知具有互补性（例如静态对隐写检测率高，而 Claude 对其识别较弱）。

## 8. 不足与局限

- **合成恶意样本的局限**：恶意集主要由人工注入生成，无法完全模拟真实攻击者的混淆深度和情境伪装，因此检测率应视为“下界”；真实世界可能仍有更难的未发现样本。
- **人口扫描覆盖不全**：138K 扫描仅限于 `SKILL.md` 内容

- **缺少消融实验**：未系统报告移除某一阶段后性能的变化幅度，无法精确量化每个阶段的边际贡献；权重为手动设定，虽避免了过拟合，但也意味着缺乏最优性保证。

## 9. 对未来工作的启示

- **静态检测的定位应是为“筛选”而非“判定”**：作者明确指出静态分析无法解决意图理解问题，未来系统应将静态预筛（每秒百级吞吐）与 LLM 语义审查（每秒 1 级）串联，形成成本高效的漏斗式流水线。
- **攻击分类法可作为对抗基准**：16 种攻击类型、三层分类法可被后续工作复用为标准测评框架，使不同检测器的评测结果具备可比性。
- **实时防御亟需运行时沙箱**：静态盲点（如主机破坏、提示注入）只能通过隔离执行、系统调用拦截、网络策略约束等运行时手段弥补；静态分析的任务应聚焦于“决定哪些技能需要沙箱化”。
- **需建立可持续更新的恶意技能语料库**：合成注入的局限表明，学术界需要从真实攻击事件、漏洞披露和社区举报中持续收集自然恶意样本，以逼近真实威胁分布。

## 10. 总体评价

SkillsMetric 是 Agent Skills 安全检测方向的一项扎实的基础性工作。其核心贡献不在于提出一种全新的检测算法，而在于首次系统性地绘制了静态分析在该问题上的**能力边界图**——既展示了多阶段加权组合在数据外泄、隐写等攻击上的强判别力（AUC 0.93），也诚实地暴露了主机破坏（0% 检测率）与提示注入（42% 检测率）这两个无法逾越的盲区。论文将评估视角从“二分类正确率”扩展到“生态级风险分布”，在 138K 真实技能上给出可复现的健康度基线（82.4% SAFE、1.75% 标记率），这一做法在同类研究中较为少见。
