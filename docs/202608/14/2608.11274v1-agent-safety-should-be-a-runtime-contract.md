## 摘要
主导范式通过RLHF、DPO或宪法AI将AI安全视为在模型训练期间灌输的一种属性。我们认为，对于执行代码、修改文件、发送消息和修改数据库的自主智能体来说，这在结构上是不够的。智能体安全应当是由执行框架执行的运行时契约，该契约有两个互补的方面。预防方面通过沙箱、权限门、输出过滤器和轨迹监视器在危险动作发生之前阻止它们。证据方面要求有可验证的证据证明好的动作确实发生了，并将任务提交限制在硬性证据上，如测试运行、日志捕获、文件差异和引文基础。我们将这一立场建立在四条公开证据线上，并在补充JSON文件中提供了行级协议和数据：对52起记录的AI智能体和LLM安全事件的调查，一项虚假完成审计包含31个无争议核心案例加一个争议性说明案例，对12个公共智能体系统和执行框架的轨迹模式审计，以及对NeurIPS、ICML和ICLR 2023-2025年接收的所有28,560篇论文的标题级审计，显示训练时间与部署时间发表之间存在合并的8-12倍不平衡。之前需要强制安全性的两个社区，计算机安全和实验科学，都收敛于同时具有预防和证据要素的运行时契约；自主智能AI现在面临同样的压力。我们形式化了智能体轨迹模式与证据链，提出了基于标准监视器组合的组合式门控命题，并概述了研究议程。自主智能体中安全性的正确单位是带有可检查证据的轨迹，而不是模型。

## Abstract
The dominant paradigm treats AI safety as a property to be instilled during model training via RLHF, DPO, or Constitutional AI. We argue this is structurally insufficient for autonomous agents that execute code, mutate files, send messages, and modify databases. Agent safety should be a runtime contract enforced by the harness, and the contract has two complementary faces. The preventive face blocks dangerous actions before they happen via sandboxes, permission gates, output filters, and trajectory monitors. The evidential face requires verifiable proof that good actions actually happened, gating task submission on hard evidence such as test runs, log captures, file diffs, and citation grounding. We ground the position in four lines of public evidence, with row-level protocols and data released in the supplementary JSON files: a survey of 52 documented AI-agent and LLM safety incidents, a false-completion audit with 31 non-contested core cases plus one disputed illustrative case, a trajectory-schema audit of 12 public agent systems and harnesses, and a title-level audit of all 28,560 papers accepted at NeurIPS, ICML, and ICLR 2023-2025 showing a pooled 8-12x imbalance between training-time and deployment-time publication. Two prior communities that needed to enforce safety, computer security and the experimental sciences, converged on runtime contracts with both preventive and evidential elements; agentic AI is now under the same pressure. We formalize an Agent Trajectory Schema and Evidence Chain, state a compositional gating proposition based on standard monitor composition, and outline a research agenda. The right unit of safety in agentic AI is the trajectory-with-checkable-evidence, not the model.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：当前 AI 安全研究的主流范式是“模型级对齐”，即通过 RLHF、DPO、宪法 AI 等技术在训练阶段将安全性内化为模型的属性。作者认为，这一范式对于能够自主执行代码、修改文件、发送消息、操作数据库的智能体（Agent）而言，在结构上是不充分的。
- **关键主张**：智能体安全不应是模型的内在属性，而应是**由执行框架（harness）在运行时强制执行的契约**。该契约包含两个互补的方面：
  - **预防面**：在危险动作发生前阻止它（沙箱、权限门、输出过滤器、轨迹监视器）。
  - **证据面**：在任务完成前要求可验证的硬证据（测试运行、日志捕获、文件差异、引用回溯）。
- **背景支撑**：论文回顾了两个已有先例：计算机安全从“可信组件正确性”转向“纵深防御”的运行时控制；实验科学从“基于声誉的断言”转向“预注册、可复现证据”的契约体系。智能体 AI 正面临同样的结构性压力。
- **核心论断**：安全性的正确单位不是模型，而是“**带可检查证据的轨迹**”（trajectory-with-checkable-evidence）。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **总体框架**：提出“双面安全框架”（Two-Faced Harness），包括预防性层和证据性层，二者组合形成运行时契约。
- **预防面 —— 机制分类学**：
  - 按时机分为四类机制：
    - **预防性**（Preventive）：输入过滤、工具白名单、权限门、提示注入分类器；
    - **检测性**（Detective）：执行追踪、异常检测、行为画像、输出分类；
    - **纠正性**（Corrective）：人机升级、自动回滚、会话终止；
    - **结构性**（Structural）：沙箱执行、资源配额、网络隔离、最小权限默认。
  - 引入五条 Saltzer–Schroeder 设计原则：纵深防御、最小权限、故障安全默认、完全中介、可审计性。
- **证据面 —— 形式化定义**：
  - **Agent 轨迹（Agent Trajectory）**：有限事件序列 τ = (e₁, ..., e_T)，每个事件 eᵢ = (kᵢ, tᵢ, pᵢ, hᵢ) 包含类型、时间戳、载荷、哈希；哈希满足 hᵢ = H(eᵢ, hᵢ₋₁)，形成哈希链，任何篡改都会使后续哈希失效。
  - **硬证据 vs 软证据**：硬证据由确定性验证器（deterministic verifier）对事件进行 ACCEPT/REJECT 判定，不依赖模型内部状态；软证据（如思维链、模型自述）依赖对模型输出内容的信任。
  - **证据链（Evidence Chain）**：轨迹中满足任务所有证据需求的子序列 η；执行框架只有在能构造并通过验证的证据链时才接受任务提交。
- **组合式门控（Compositional Gating）**：
  - 将每个预防层建模为确定性有限自动机（harness monitor），每个证据门建模为证据链检查器。
  - 在互不共享观察字母表的条件下，组合验证是多项式复杂度；共享事件时退化为 assume-guarantee 推理；一般情况为指数复杂度，但对状态数较小的实际部署监控器是可处理的。
- **应用示例（代码补丁提交）**：
  - 预防层示例：Docker 沙箱无网络访问 → 工具白名单（read/write/grep/pytest 自动批准，rm/git push/curl 需人工审批）→ 文件系统范围守卫 → 行为监控（凭据读取-写入模式）→ 告警自动回滚。
  - 证据面示例：文件写入 diff + 测试套件运行调用 + 测试退出码输出 + commit 哈希，四类事件构成证据链；任务 schema 为“存在 commit 且测试退出码为 0 且 diff 非空”。

## 3. 实验设计：数据集、场景与基准

论文提供**四条公开证据线**，每条都有独立的审计协议和行级 JSON 数据：

2. **32 例虚假完成审计**（False-Completion Audit）：

   - 失败类别分布：幻觉 13、损坏 8、副作用 5、部分完成 4、奖励黑客 2；
   - 证据需求分布：引用回溯 8、日志捕获 8、测试运行 7、人工审批 5、外部状态 3、截图 1；
   - 典型案例：Replit 数据库删除、Amazon Kiro 争议事件、Mata v. Avianca 虚假引用案、Air Canada 聊天机器人虚假政策、Cursor 支持机器人幻觉、Whisper 音频转写幻觉、SWE-bench Verified 虚假补丁。

3. **12 个公共智能体系统轨迹模式审计**（Trajectory-Schema Audit）：

   - 结果：训练时对齐工作约占对齐标签论文的 58–64%，部署时 harness 机制约占 5–8%，合并的训练/部署不平衡约为 **8–12 倍**；每个单元方向一致但比值有差异。

## 6. 论文的主要结论与发现

- **训练时对齐在结构上不足以支撑智能体安全**：论文归纳出五个不可通过模型规模扩张弥合的错配：
  1. 统计代理（reward model） vs 形式规范（权限规则）——代理优化服从 Goodhart 定律，失败是静默累积的；
  2. 训练分布（闭世界） vs 开放世界部署——OOD 鲁棒性随 RLHF 增强而下降，红队攻击成功率不随模型规模下降；
  3. 不可验证的内部独白 vs 可重放轨迹——模型自述不可信（Apollo 的 scheming 评估、METR 的 reward hacking 审计）；
  4. 看似合理的输出 vs 可溯源的引用——幻觉的补救方式是外部硬验证（真实引用查找、测试重跑）；
  5. 单层防御 vs 纵深防御——一次越狱、微调或分布偏移即可击穿对齐。
- **运行时契约已经是被验证的解决方案**：计算机安全和实验科学两大社区都收敛于“预防 + 证据”的运行时契约结构；智能体 AI 应做出同样的架构转向。
- **部署现状与学术关注度不匹配**：生产系统已在大量使用运行时安全组件，但顶会发表仍严重偏向训练时对齐（8–12 倍不平衡），且多数公开智能体工具“能记录产物却不设门控”。
- **安全单元应重新定义**：不是模型，而是“**带可检查证据的轨迹**”；责任边界从“是否信任模型”转向“能否验证工件”。

## 7. 优点

- **概念界定清晰**：将“模型级对齐”与“harness 基础设施”明确区分，提出预防/证据的双面对称框架，具有较强的理论洞察力。
- **证据充分且可审计**：四条证据线覆盖事故记录、系统行为、学术发表三个层面，并公开行级 JSON 数据（编码规则、来源链接、争议标注），透明度和可复现性高。
- **形式化程度适中**：对轨迹、硬/软证据、证据链给出明确的形式定义（哈希链保证完整性），组合式门控命题有可验证的复杂度分析，为后续工程和理论研究提供语言基础。
- **与既有工程实践接轨**：框架不是凭空设计，而是对已存在的生产系统行为（GitHub Copilot 的 CI 门控、OSWorld 的执行评分、Aider 的逐编辑 git 提交等）的归纳和提炼，落地成本论述较可信。
- **论证视角独特**：将计算机安全史和科学方法论史作为类比论证的支撑，说明“运行时契约”是面对高风险操作时的普遍结构性答案，而非仅针对 LLM 的权宜之计。
- **对反例的预处理**：在反驳部分处理了“超对齐必要性”“责任转移”“成本”“创造性任务无 schema”等五类常见反对意见，考虑较全面。

- **形式框架仍偏简化**：
  - 假设监控器的观察字母表互不相交，实际系统事件往往是共享的，论文虽提及 assume-guarantee 回退但未展开具体方法；
